# 알림함 규칙

## NOTIFICATION-001 검수 결과 알림 생성

- 규칙: 관리자가 게시물을 승인하거나 반려하면 작성자의 알림함에 해당 검수 결과를 한 건 저장한다. 검수 상태 변경·관리자 감사 로그·알림 저장은 하나의 트랜잭션으로 처리한다. 같은 회원에게 같은 검수 사건의 알림을 중복 저장하지 않는다.
- 적용 범위: 관리자 게시물 검수 확정, 승인·반려 알림함 기록
- 예외: 검수가 실패하거나 트랜잭션이 롤백되면 알림도 남지 않는다. 이번 규칙은 검수 결과 알림함 기록에 적용하며 주제 알림과 푸시 발송은 포함하지 않는다.
- 결정 기록: [검수 결과 알림함 도입과 보관 기준](../decisions/2026-09-29-notification-inbox.md)

## NOTIFICATION-002 본인 알림 조회

- 규칙: 탈퇴하지 않은 회원은 본인의 알림만 최신순으로 조회한다. 목록에는 게시물 사진의 썸네일 URL과 읽은 시각을, 상세에는 원본 사진 URL과 반려 사유를 제공한다. 게시물이 삭제되면 연결된 알림은 즉시 목록·상세·미읽음 상태에서 제외하되, 알림 기록은 보관 기간까지 유지한다.
- 적용 범위: 알림 목록·상세·미읽음 상태 조회
- 예외: 정지 회원도 본인의 알림을 조회할 수 있다. 다른 회원의 알림과 삭제된 게시물의 알림 상세는 찾을 수 없는 것으로 처리하며 탈퇴 회원의 인증된 알림함 접근은 차단한다. 반려 사유는 승인 알림에는 없다.
- 결정 기록: [검수 결과 알림함 도입과 보관 기준](../decisions/2026-09-29-notification-inbox.md)

## NOTIFICATION-003 읽음 상태

- 규칙: 회원은 알림함에 표시되는 본인의 알림 한 건 또는 표시되는 미읽음 알림 전체를 읽음 처리할 수 있다. 이미 읽은 알림을 다시 처리해도 최초 읽은 시각을 유지한다.
- 적용 범위: 단건 읽음, 전체 읽음, 미읽음 상태
- 예외: 다른 회원의 알림과 삭제된 게시물의 알림은 단건 읽음 처리할 수 없다. 알림을 조회하는 것만으로는 읽음 처리하지 않는다.
- 결정 기록: [검수 결과 알림함 도입과 보관 기준](../decisions/2026-09-29-notification-inbox.md)

## NOTIFICATION-004 알림함 보관과 삭제

- 규칙: 일반 회원의 알림은 생성 시각부터 60일이 지난 뒤 정리한다. 탈퇴 회원의 남아 있는 알림은 생성 시각과 관계없이 탈퇴 시각부터 30일이 지난 뒤 정리한다.
- 적용 범위: 알림함 데이터의 주기적 삭제
- 예외: 탈퇴 요청 시 알림을 즉시 지우지 않는다. 두 기간의 정확한 경계 시각에는 보관하고, 경계 시각이 지난 알림을 다음 정리 실행 때 삭제한다. 이미 삭제된 알림을 탈퇴 때문에 복원하지 않는다.
- 결정 기록: [검수 결과 알림함 도입과 보관 기준](../decisions/2026-09-29-notification-inbox.md)

## NOTIFICATION-005 현재 로그인 기기 등록·해제

- 규칙: 탈퇴하지 않은 회원은 유효한 로그인으로 현재 앱의 FCM 토큰을 등록·갱신한다. 회원과 로그인 ID는 액세스 토큰에서 식별하며 요청 본문으로 받지 않는다. 로그인 하나에 기기 등록 하나를 유지하고, 같은 로그인 연결에서 반복 등록하거나 토큰을 교체해도 최초 등록 시각을 유지한다. 같은 FCM 토큰을 다른 로그인에 등록하면 이전 기기 행을 삭제한다. 기기 연결을 해제할 때는 토큰만 비우거나 비활성 행을 남기지 않고 기기 행 전체를 삭제한다. 로그아웃 후 재로그인하거나 해제된 로그인으로 다시 등록하면 새 기기 행을 생성한다. 앱 설치 식별자와 플랫폼은 등록 요청으로 받지 않는다. 로그아웃하면 해당 로그인 기기 행을 삭제하며, 같은 로그인의 RT 폐기와 함께 처리한다. 갱신 요청에서 RT 재사용·비활동 만료·절대 만료를 감지하여 로그인을 폐기할 때도 해당 기기 해제를 함께 처리한다. 다른 로그인의 기기는 유지한다. 회원 탈퇴 시에는 해당 회원의 모든 기기 행을 삭제한다. 회원 탈퇴·전체 RT 폐기·기기 해제를 하나의 트랜잭션에서 처리한다.
- 적용 범위: `PUT /api/v1/push-devices/current`, `POST /api/v1/auth/refresh`, `POST /api/v1/auth/logout`, `DELETE /api/v1/users/me`, 로그인 후 기기 등록, FCM 토큰 변경·앱 재시작에 따른 갱신
- 예외: 정지 회원도 등록할 수 있다. 탈퇴 회원의 등록은 차단한다. 로그인 ID가 없는 이전 JWT는 사용 가능한 리프레시 토큰으로 자동 갱신한 뒤 기기를 등록할 수 있다. 로그인 ID가 잘못되었거나 해당 회원의 사용 가능한 리프레시 토큰이 없는 로그인은 등록할 수 없다. 리프레시 토큰의 만료·폐기·재사용 등으로 인증 갱신이 거절될 때 재로그인한다. 기기 등록 실패가 이미 성공한 로그인을 취소하지는 않는다. 등록 응답에 FCM 토큰을 반환하지 않는다. 로그아웃은 액세스 토큰 없이 RT로 처리한다. 만료·회전·폐기된 RT도 DB에서 해당 로그인을 식별할 수 있으면 연결 기기를 해제한다. 알 수 없는 RT는 다른 기기에 영향을 주지 않고 204를 반환한다. 반복 로그아웃은 기기가 없는 상태를 유지하며, 토큰이 다른 로그인으로 이동했다면 새 연결은 해제하지 않는다. 기기 행 삭제가 실패하면 RT 폐기도 롤백한다. 재사용·만료 감지의 인증 오류 응답에도 RT 폐기·기기 해제는 함께 커밋한다. 정상 갱신은 기기 연결을 유지하고, 갱신 요청에서 만료를 감지하기 전까지 만료 시각만으로 기기를 자동 해제하지는 않는다. 탈퇴 시에는 이미 RT가 폐기된 로그인에 남은 기기 행도 삭제한다. 다른 회원에게 옮겨진 토큰 연결은 유지한다. 탈퇴 중 기기 행 삭제가 실패하면 회원 탈퇴·소셜 연결 삭제·RT 폐기도 롤백한다. 알림함 기록의 보관은 NOTIFICATION-004를 따른다. 탈퇴 회원의 인증된 기능 접근은 차단하지만 비로그인 공개 피드 조회는 유지한다.
- 결정 기록: [로그인별 푸시 기기 등록](../decisions/2026-09-30-push-device-registration.md), [재사용·만료 감지 시 푸시 기기 해제](../decisions/2026-10-01-session-revocation-push-cleanup.md), [로그인별 등록 유지와 해제 시 연결 제거](../decisions/2026-10-06-push-device-connection-cleanup.md)

앱의 요청 순서와 토큰 갱신 처리는 [푸시 기기 등록 연동 안내](../guides/push-device-registration.md)를 참고한다.

## NOTIFICATION-006 본인 푸시 수신 설정 조회·수정

- 규칙: 탈퇴하지 않은 회원은 본인 계정에 저장된 주제 푸시 수신 여부와 게시물 승인·반려 결과 푸시 수신 여부를 조회·수정한다. 수정 요청에 값이 있는 항목만 변경하고 생략하거나 null인 항목은 기존 값을 유지한다. 변경할 값이 하나도 없으면 요청을 거부한다. 두 설정의 최초 값은 모두 켜짐이다. 설정은 기기별이 아닌 회원 계정 단위로 저장한다.
- 적용 범위: `GET /api/v1/notification-settings`, `PATCH /api/v1/notification-settings`, 앱의 알림 설정 화면
- 예외: 정지 회원도 조회·수정할 수 있다. 탈퇴 회원과 존재하지 않는 회원은 인증 오류로 거부한다. 회원 ID는 액세스 토큰에서 식별하며 요청으로 받지 않는다. 기기 등록 여부와 로그인 ID의 유무는 조회·수정 조건이 아니다. 서로 다른 설정의 수정 요청이 겹쳐도 각 변경을 유지하며, 같은 항목은 나중에 처리된 요청의 값으로 저장한다. 같은 값의 반복 요청도 허용한다. 수정 성공은 본문 없는 204로 응답한다. 반환값은 서비스에 저장된 설정이며 운영체제의 알림 권한이나 실제 푸시 수신 성공을 나타내지 않는다. 알림함의 조회·보관 기준은 별도 규칙을 따른다.
- 결정 기록: [회원별 푸시 수신 설정 조회·수정](../decisions/2026-09-30-notification-settings.md)
