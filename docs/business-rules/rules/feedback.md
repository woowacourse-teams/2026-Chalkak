# 피드백 규칙

## FEEDBACK-001 제출 자격

- 규칙: 탈퇴하지 않은 회원은 본인 계정으로 인증해 피드백을 제출할 수 있다. 이용이 정지된 `BANNED` 회원도 제출할 수 있다.
- 적용 범위: 앱 마이페이지의 피드백 제출
- 예외: 인증하지 않은 요청과 탈퇴한 회원의 요청은 거절한다. 제출 횟수와 간격에는 제한을 두지 않는다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md)

## FEEDBACK-002 제출 내용

- 규칙: 피드백은 유형 구분 없이 내용 한 건만 받는다. 앞뒤 공백을 제거한 후 Unicode code point 기준 1~1000자를 허용하고, 앞뒤 공백을 제거해 저장한다.
- 적용 범위: 피드백 제출
- 예외: 공백만 입력한 요청은 거절한다. 첨부 파일, 연락처, 답변 요청 여부는 받지 않는다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md)

## FEEDBACK-003 보관과 조회 범위

- 규칙: 접수한 피드백은 제출 시각과 제출한 회원을 기록해 보관한다. 제출한 회원은 자신의 피드백을 조회할 수 없다.
- 적용 범위: 피드백 보관, 앱의 피드백 조회
- 예외: 피드백의 수정·삭제·답변은 제공하지 않는다. 회원이 탈퇴해도 접수된 피드백은 삭제하지 않으며, 탈퇴 시 회원 정보 처리는 [회원 규칙](user.md)을 따른다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md)

## FEEDBACK-004 관리자 조회

- 규칙: 관리자는 접수된 피드백을 내용, 제출 시각, 제출한 회원의 식별자·이메일·상태·앱 버전과 함께 최신순 또는 오래된 순으로 조회할 수 있다. 정지·탈퇴 회원이 남긴 피드백도 함께 조회한다.
- 적용 범위: 관리자 피드백 조회
- 예외: 관리자는 피드백을 조회만 할 수 있고 상태 변경·답변·삭제는 할 수 없다. 상태를 바꾸는 작업이 없으므로 감사 로그를 남기지 않는다. 접근 권한은 [관리자 규칙](admin.md)을 따른다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md)
