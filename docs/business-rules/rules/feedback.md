# 피드백 규칙

## FEEDBACK-001 제출 자격

- 규칙: 탈퇴하지 않은 회원은 본인 계정으로 인증해 피드백을 제출할 수 있다. 이용이 정지된 `BANNED` 회원도 제출할 수 있다. 정상·정지 회원 모두 회원별 1분에 1건, 최근 24시간에 최대 5건을 접수할 수 있다.
- 적용 범위: 앱 마이페이지의 피드백 제출
- 예외: 인증하지 않은 요청과 탈퇴한 회원의 요청은 거절한다. 성공적으로 저장한 접수만 집계하며 제한 초과·입력 오류 등 실패 요청은 저장하지 않는다. 최근 24시간은 자정 기준이 아닌 접수 시각 기준이고, 정확히 1분 또는 24시간이 지나면 해당 제한이 해제된다. 두 제한이 겹치면 모두 해제되는 시각을 안내한다. 초과 응답은 기존 `400 / BUSINESS_ERROR` 형식이며 메시지에 다음 접수 가능 시각을 UTC `Instant`로 포함한다. 안내 시각은 소수 초가 있을 때만 다음 초로 올려 표시하며, 실제 제한 판정은 원래 접수 시각 기준을 유지한다. 고객센터 접수 Slack 알림과 관리자 개별 문의 차단·해제 기능은 제공하지 않는다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md), [회원별 접수 제한](../decisions/2026-11-03-feedback-submission-limits.md)

## FEEDBACK-002 제출 내용

- 규칙: 피드백은 유형 구분 없이 내용 한 건만 받는다. 앞뒤 공백을 제거한 후 Unicode code point 기준 1~1000자를 허용하고, 앞뒤 공백을 제거해 저장한다.
- 적용 범위: 피드백 제출
- 예외: 공백만 입력한 요청은 거절한다. 첨부 파일, 연락처, 답변 요청 여부는 받지 않는다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md)

## FEEDBACK-003 보관과 조회 범위

- 규칙: 접수한 피드백은 제출 시각과 제출한 회원을 기록해 보관한다. 탈퇴하지 않은 회원은 삭제되지 않은 본인 문의 목록과 상세만 조회할 수 있고, 본인 문의를 소프트 딜리트할 수 있다. 정지 회원도 동일하게 허용한다. 삭제 후 사용자 목록·상세에서 제외하되 원문·작성자·접수 시각은 보존한다. 삭제 성공은 `204`이며, 본인 문의를 반복·동시 삭제해도 성공하고 최초 삭제 시각을 유지한다. 목록은 접수 시각과 식별자 내림차순이며, 1부터 시작하는 페이지 번호와 페이지당 건수(기본 20건·최대 100건)를 받는다. 상세는 문의 식별자·내용·접수 시각과 현재 답변 내용·등록 시각을 제공한다. 미답변이면 `answerContent`와 `answeredAt`이 모두 null이다. 목록에는 답변 필드를 제공하지 않는다. 도입 전 피드백은 전환 마이그레이션의 DB 트랜잭션 시작 시각보다 접수 시각이 이른 기록이다. 같은 테이블에 보존하고 소프트 딜리트하여 사용자 조회에서 제외한다. 기준과 같거나 이후에 접수된 문의는 배포 중 이전 앱이 저장했더라도 사용자 조회에 남긴다. 관리자는 기존 조회에서 해당 기록을 계속 확인할 수 있다.
- 적용 범위: 피드백 보관, 앱의 본인 문의 목록·상세 조회와 삭제
- 예외: 인증하지 않았거나 탈퇴한 회원은 목록·상세·삭제를 이용할 수 없다. 상세의 타인·삭제·없는 문의, 삭제의 타인·없는 문의는 존재 여부와 원문을 노출하지 않고 모두 `404 / BUSINESS_ERROR / 문의를 찾을 수 없습니다.`로 응답한다. 잘못된 형식 또는 축약된 UUID는 `400 / BUSINESS_ERROR`로 거절한다. 삭제된 문의도 접수 제한 횟수에 포함하며 삭제로 제한이 초기화되지 않는다. 사용자 문의 수정은 제공하지 않는다. 회원이 탈퇴해도 접수된 피드백은 물리 삭제하지 않으며, 탈퇴 시 회원 정보 처리는 [회원 규칙](user.md)을 따른다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md), [본인 목록과 기존 피드백 전환](../decisions/2026-11-03-feedback-own-list.md), [본인 문의 상세 조회](../decisions/2026-11-03-feedback-own-detail.md), [본인 문의 삭제](../decisions/2026-11-03-feedback-own-deletion.md), [전환 시각 경계](../decisions/2026-11-03-feedback-cutover-boundary.md)

## FEEDBACK-004 관리자 조회

- 규칙: 관리자는 접수된 피드백을 내용, 제출 시각, 문의 삭제 시각과 제출한 회원의 식별자·이메일·상태·앱 버전과 함께 최신순 또는 오래된 순으로 조회할 수 있다. 사용자 식별자를 생략하면 전체 목록, 전달하면 해당 사용자의 목록을 조회한다. 삭제된 문의와 정지·탈퇴 회원이 남긴 피드백도 함께 조회한다. 문의 식별자로 상세를 조회하면 목록과 같은 문의·작성자 정보 및 문의 원문을 제공하며, 상세에만 현재 답변 내용과 등록 시각을 포함한다. 미답변이면 두 값은 모두 null이다. 문의 삭제 시각은 삭제되지 않았으면 null이다.
- 적용 범위: 관리자 피드백 목록·상세 조회
- 예외: 해당 사용자의 문의가 없거나 존재하지 않는 사용자 식별자로 필터링하면 오류가 아닌 빈 목록을 반환한다. 없는 문의의 상세는 `404 / BUSINESS_ERROR / 문의를 찾을 수 없습니다.`로 응답한다. 사용자 필터의 잘못되거나 축약되거나 비어 있는 UUID와 상세 경로의 잘못되거나 축약된 문의 UUID는 기존 400 오류로 거절한다. 목록의 기존 페이지·정렬·작성자 필드는 유지한다. 조회 자체는 감사 로그를 남기지 않으며, 관리자 문의 삭제는 [FEEDBACK-005](#feedback-005-관리자-문의-삭제)를 따른다. 접근 권한은 [관리자 규칙](admin.md)을 따른다.
- 결정 기록: [피드백 수집 도입](../decisions/2026-09-16-feedback-collection.md), [관리자 사용자별 문의 목록](../decisions/2026-11-03-admin-feedback-user-filter.md), [관리자 문의 상세](../decisions/2026-11-03-admin-feedback-detail.md)

## FEEDBACK-005 관리자 문의 삭제

- 규칙: ADMIN은 정상·정지·탈퇴 회원이 남긴 문의를 소프트 딜리트할 수 있다. 삭제 후 사용자 목록·상세에서는 숨기고 원문·작성자·접수 시각은 보존하여 관리자는 삭제 표시와 함께 조회할 수 있다. 성공 응답은 본문 없는 `204`이며 요청 본문과 별도 삭제 사유는 받지 않는다. 삭제와 관리자 감사 기록은 같은 트랜잭션으로 저장하고, 어느 한쪽이 실패하면 둘 다 반영하지 않는다.
- 적용 범위: `DELETE /api/v1/admin/feedbacks/{feedbackId}`, 관리자 문의 삭제와 감사 기록
- 예외: 없는 문의는 `404 / BUSINESS_ERROR / 문의를 찾을 수 없습니다.`이며, 잘못되거나 축약된 UUID는 `400 / BUSINESS_ERROR`로 거절한다. 인증하지 않은 요청은 401, 일반 회원은 정상·정지·탈퇴 여부와 관계없이 403으로 거절한다. 사용자나 관리자가 이미 삭제한 문의를 반복·동시 삭제해도 `204`이며 최초 삭제 시각을 유지하고 새 감사 기록을 만들지 않는다. 삭제된 문의도 접수 제한 횟수에 포함한다. 문의의 소프트 딜리트와 관련 답변 알림 행의 물리 삭제는 같은 트랜잭션에서 반영한다(NOTIFICATION-018). 복구·물리 삭제는 제공하지 않는다.
- 결정 기록: [관리자 문의 삭제와 감사](../decisions/2026-11-03-admin-feedback-deletion.md)


## FEEDBACK-006 관리자 최초 답변

- 규칙: 관리자는 삭제되지 않은 문의에 현재 답변을 한 건 등록할 수 있다. 앞뒤 공백을 제거한 뒤 Unicode 코드 포인트 기준 1~3,000자이며, 성공 응답은 204다. 답변, 사용자 알림함 항목, 관리자 감사 기록을 같은 트랜잭션에서 저장한다. 감사에는 관리자·대상과 답변 등록 시각 전후 값을 남기며 문의·답변 원문은 복제하지 않는다.
- 적용 범위: `POST /api/v1/admin/feedbacks/{feedbackId}/answer`와 문의 답변 알림함 항목
- 예외: 정지 회원의 문의는 답변할 수 있다. 삭제된 문의·탈퇴 회원 문의·이미 답변한 문의는 400, 없는 문의는 404다. 인증 없는 요청은 401이며 일반 회원은 403이다. 문의 행을 잠가 동시 답변에서도 한 건만 저장한다. 작성자의 탈퇴 여부는 답변 처리 중 조회하며, 확인 이후 탈퇴와 겹친 답변은 완료될 수 있다. 발송 시점의 회원 상태는 푸시 발송 과정에서 다시 확인한다.
- 결정 기록: [관리자 답변과 알림 보관](../decisions/2026-11-04-feedback-answer-notification.md)
