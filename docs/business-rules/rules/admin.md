# 관리자 규칙

## ADMIN-001 접근 권한

- 규칙: 로그인 외 관리자 기능은 `ADMIN` 권한으로 인증된 관리자만 사용할 수 있다. 일반 회원은 접근할 수 없으며 관리자별 세부 역할은 구분하지 않는다.
- 적용 범위: 관리자 API 전체
- 예외: 인증 우회는 설정으로 명시한 로컬·테스트 환경에서만 허용한다.
- 결정 기록: 없음

## ADMIN-002 회원 상태 관리

- 규칙: 관리자는 탈퇴하지 않은 회원을 `ACTIVE`에서 `BANNED`로 차단하거나 `BANNED`에서 `ACTIVE`로 해제할 수 있다. 탈퇴 회원은 `deletedAt`을 기준으로 `WITHDRAWN`으로 표시한다.
- 적용 범위: 관리자 회원 조회와 상태 변경
- 예외: 같은 상태로의 변경과 `WITHDRAWN` 회원의 상태 변경은 허용하지 않는다. 차단과 해제에는 공백만이 아닌 사유가 필요하며, 앞뒤 공백을 제거한 후 Unicode code point 기준 최대 500자까지 허용한다.
- 결정 기록: 없음

## ADMIN-003 게시물 검수

- 규칙: 관리자는 `PENDING` 게시물을 한 번만 `APPROVED` 또는 `REJECTED`로 확정할 수 있다.
- 적용 범위: 관리자 게시물 검수
- 예외: 승인에는 사유를 입력할 수 없다. 반려에는 앞뒤 공백을 제거한 1~500자의 사유가 필요하다.
- 결정 기록: 없음

## ADMIN-004 게시물 조회와 삭제

- 규칙: 관리자는 `PENDING`, `APPROVED`, `REJECTED` 게시물과 이미 삭제된 게시물을 조회할 수 있다. `PENDING`, `APPROVED`, `REJECTED` 게시물은 사유와 함께 삭제할 수 있다. 삭제 사유는 필수이며 공백만 입력할 수 없다. 앞뒤 공백을 제거하기 전 Unicode code point 기준 최대 500자까지 허용하고, 저장 시 앞뒤 공백을 제거한다.
- 적용 범위: 관리자 게시물 관리
- 예외: `VALIDATING` 게시물은 관리자 조회·검수·삭제 대상이 아니다. 삭제는 게시물과 사진을 논리 삭제하고 좋아요를 제거하지만 실제 미디어 파일은 보존한다. 이미 삭제된 게시물에 유효한 삭제 요청을 반복하면 최초 삭제 결과를 유지하고 감사 로그를 추가하지 않는다. 반복 요청도 삭제 사유 조건을 충족해야 한다.
- 결정 기록: 없음

## ADMIN-005 주제 관리

- 규칙: 관리자는 주제를 생성하고 공개 전 수정·삭제할 수 있다. 세부 상태와 날짜 제약은 [주제 규칙](topic.md)을 따른다.
- 적용 범위: 관리자 주제 관리
- 예외: 주제 삭제에는 앞뒤 공백을 제거한 1~500자의 사유가 필요하다.
- 결정 기록: 없음

## ADMIN-006 감사 로그

- 규칙: 게시물 승인·반려·삭제, 회원 차단·해제, 주제 생성·수정·삭제는 처리 관리자, 행위, 대상, 사유, 변경 전후 상태, 처리 시각, 요청 식별자를 감사 로그로 남긴다.
- 적용 범위: 관리자 변경 작업
- 예외: 민감정보, 토큰, 비밀번호, 이미지 URL, 스토리지 키와 바이너리는 기록하지 않는다.
- 결정 기록: 없음

## ADMIN-007 변경과 감사의 일관성

- 규칙: 관리자 변경과 감사 로그는 같은 트랜잭션에서 처리한다. 어느 한쪽이 실패하면 둘 다 반영하지 않으며 감사 로그는 수정·삭제하지 않는다.
- 적용 범위: 관리자 게시물·회원·주제 변경
- 예외: 없음
- 결정 기록: 없음

## ADMIN-008 검수 요청 알림

- 규칙: 관리자 알림이 활성화된 환경에서는 게시물이 `PENDING`에 진입한 변경이 커밋된 후 관리자 검수 요청 알림을 발송한다.
- 적용 범위: 처리 완료된 사진의 게시물 생성, 게시물 이미지 처리 완료, 관리자 알림
- 예외: 알림이 비활성화된 환경에서는 발송하지 않는다. 알림 발송 실패는 이미 완료된 게시물 변경을 되돌리지 않는다.
- 결정 기록: 없음
