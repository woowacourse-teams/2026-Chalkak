# NOTIFICATION-011·016 직접 발행 회차의 사건 식별자 유지

- 결정일: 2026-10-26
- 상태: 확정
- 변경 전: 주제·리마인더는 서비스 실행마다 랜덤 UUID로 사건 ID를 만들었다. 같은 프로세스의 회원별 메시지는 사건 ID를 공유하지만, 재시작 후 같은 회차를 실행하면 다른 사건 ID가 생겼다.
- 변경 후: 알림 종류·설정 또는 리마인더 ID·원래 회차 예정 시각으로 사건 ID를 결정한다. 같은 회차는 재시작·배포 후에도 같은 ID를 사용한다. 주제의 대상 주제 ID 대신 설정 ID를 사용해, 같은 주제의 여러 발송 설정을 구분한다. 리마인더도 문구·대상·실제 실행 시각은 입력에서 제외한다. 원래 예정 시각이 바뀐 새 회차와 다른 설정·종류는 다른 사건이다.
- 변경 이유: SQS 메시지 ID는 재발행 때 바뀔 수 있고 랜덤 사건 ID도 재시작 후 바뀌므로, 후속 `(eventId, userId)` 발송 이력이 같은 사건을 찾을 수 없다. 저장·조회 없이 회차를 동일하게 식별하도록 UTF-8의 고정된 입력 형식과 이름 기반 UUID를 사용한다. 보안 토큰이나 시간 순서 정렬용 식별자로 사용하지 않는다.
- 영향 범위: 주제·리마인더의 새 SQS 메시지와 FCM `data.eventId`, 조사 로그. UUID 필드·응답 구조·클릭 이동·30분 기한·프로세스 메모리의 회차 시도 제한은 유지한다. 기존 큐에 있는 랜덤 ID는 소급 변경하지 않으므로 전환 전후 메시지를 같은 ID로 통합하지 못한다.
- 남은 한계: 동일한 사건 ID만으로 중복 발행·FCM 중복 요청·배너 중복을 막지 않는다. SQS 중복 발행과 Best Effort 유실 가능성은 남고, Worker의 발송 이력·Lease·결과 불명 재처리는 후속 #826에서 구현·검증한다. 이번 변경은 전체 Exactly-once 보장이 아니다.
