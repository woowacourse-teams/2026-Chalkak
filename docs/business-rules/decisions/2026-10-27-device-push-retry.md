# NOTIFICATION-008 기기별 결과에 따른 재처리

- 결정일: 2026-10-27
- 상태: 확정
- 변경 전: 하나라도 FCM이 수락하면 사용자 작업을 완료하고 다른 기기의 일시 실패를 재처리하지 않았다. 기기 수락 기록만 남은 중단 작업도 사용자 완료로 복구했다.
- 변경 후: 기기별 JSON 기록을 유지하고 수락·영구 실패·무효 토큰·생략이 기록된 기기는 재발송하지 않는다. 일시 실패·결과 불명인 현재 대상 기기는 다른 기기의 수락 여부와 관계없이 기존 SQS 정책으로 재처리한다. 재처리할 현재 대상이 없으면 사용자 처리를 종료한다. 중단 뒤에는 수락 기기는 건너뛰고 미완료 기기를 이어 처리한다.
- 변경 이유: 여러 기기로 발송할 때 한 기기의 수락 때문에 다른 기기의 일시 실패를 포기하지 않도록 한다. 기기별 기록을 조사뿐 아니라 재처리 대상 판단에 사용한다. 추가 DB 기록 비용과 실제 기기 수신 보장의 한계는 감수한다.
- 영향 범위: 공통 Worker를 사용하는 승인·반려·주제·공지·리마인더·AI 리뷰 결과. API·SQS·FCM 필드 형식은 유지한다. 미완료 사건은 현재 등록 기기와 최신 발송 조건으로 판단하고, 완료된 사건에는 새 기기를 추가 발송하지 않는다. 별도 대상 스냅샷 테이블은 추가하지 않는다.
- 유지하는 경계: SQS 메시지별 최초 포함 최대 수신 10회·원래 사건 발생 후 30분 기한·Retry-After와 Lease 60초/30초 갱신. 별도 Worker·결과 불명 횟수 상한은 두지 않는다. FCM 수락 후 DB 저장 전 중단의 중복 가능성은 남는다. 기한 만료로 SQS를 먼저 삭제하면 이력에 마지막 기기 실패가 남을 수 있고, 이를 실제 수신 실패나 추가 발송 가능으로 해석하지 않는다.
