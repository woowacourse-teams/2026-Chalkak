# BANNER-003~005 배너 논리 삭제와 재등록

- 결정일: 2026-10-19
- 상태: 확정
- 변경 전: 관리자 배너 등록·목록 조회만 제공하고, 모든 저장된 배너 간 같은 URL을 거절한다.
- 변경 후: 요청 본문·사유 없이 관리자 논리 삭제를 제공한다. 삭제된 배너는 목록·URL 중복 대상에서 제외하고 새 ID로 재등록할 수 있다. 반복·동시 삭제는 최초 시각·감사 한 건을 유지하며 삭제와 감사는 함께 성공하거나 롤백된다. 외부 페이지·파일은 삭제하지 않는다.
- 변경 이유: 끝난 홍보 배너를 목록에서 내리면서 삭제 이력을 보존하고 같은 주소를 새 홍보에 사용할 수 있도록 한다. 삭제 이유를 조회하는 요구가 없어 삭제 사유 입력·저장을 제거한다.
- 영향 범위: 관리자 삭제·목록·등록, 부분 URL 고유 제약, 감사 기록. 앱 공개 목록은 후속 #678에서 제공한다. 다른 관리자 작업의 사유·민감값 검증 정책은 유지한다.
- 관련 규칙: BANNER-001, BANNER-003, BANNER-004, BANNER-005, ADMIN-006, ADMIN-007
- 관련 이슈·PR: [#677](https://github.com/woowacourse-teams/2026-Chalkak/issues/677), [PR #697](https://github.com/woowacourse-teams/2026-Chalkak/pull/697)

## 삭제 사유 제거 결정

초기 구현에서는 사유 원문을 감사에 저장하고 기존 감사 민감값 검증을 적용했다. 리뷰에서 최초 삭제와 재삭제·미존재 요청의 사유 검증 시점이 달라지는 문제가 드러났다. 공통 사유 객체로 검증을 묶거나 해시만 기록하는 방식을 비교했지만, 삭제 이유 원문을 나중에 확인해야 하는 요구가 없어 사용자가 사유 입력·기록을 제거하기로 결정했다.

삭제 API의 요청 DTO와 사유 검증을 제거하고 감사에는 null 사유를 전달한다. 삭제 이력 자체와 동일 트랜잭션·반복/동시 삭제 보장은 유지한다. 이미 적용한 마이그레이션을 수정하지 않고 후속 마이그레이션으로 배너 삭제 사유 필수 제약만 제거한다. 이 변경은 미병합 PR의 계약 정리이며 다른 도메인의 삭제 사유 정책을 바꾸지 않는다.
