# AIREVIEW-005 AI 리뷰 피드백 항목 분리

- 결정일: 2026-10-21
- 상태: 확정
- 변경 전: 완료된 리뷰의 피드백은 300자 이하 문자열 하나(`result.feedback`)였다.
- 변경 후:
  - 피드백을 한 줄 요약(`summary`, 60자 이하)과 좋았던 점(`strength`)·아쉬운 점(`weakness`)·다음 제안(`suggestion`, 각 150자 이하) 네 항목으로 나눈다. 네 항목 모두 비어 있지 않아야 하며, 글자 수는 서버가 코드포인트 기준으로 검사한다. 검사를 통과하지 못한 모델 출력은 형식 오류로 실패한다([AIREVIEW-005](../rules/ai-review.md#aireview-005-결과-표시)).
  - 응답의 `result.feedback`은 문자열에서 `{summary, strength, weakness, suggestion}` 객체로 바뀐다. 점수·항목·독특한 시각 등 나머지 응답 필드는 그대로다.
  - 모델 출력 스키마를 1에서 2로 올린다.
- 변경 이유:
  - 앱 화면이 한 줄 요약과 세 섹션(좋았던 점·아쉬운 점·다음엔 이렇게)으로 구성되는데, 문자열 하나는 앱에서 항목별로 안정적으로 나눌 수 없다.
  - 모델이 항목을 따로 채우게 하면 엄격한 출력 스키마(strict)가 네 항목의 존재를 보장한다. 글자 수 제한은 이 스키마가 지원하지 않아 서버가 검사한다.
- 영향 범위: `POST`·`GET /api/v1/posts/{postId}/ai-review`의 `result.feedback`, 관리자 AI 프롬프트 미리보기 응답의 `result.feedback`, 모델 출력 스키마.
  - API 의미 변경: `result.feedback`의 타입이 문자열에서 객체로 바뀐다. 앱은 아직 이 API에 연동하지 않았으므로 깨지는 클라이언트가 없어 `v1`에 반영한다.
  - 프롬프트 버전: 출력 스키마가 2로 바뀌어 기존 프롬프트 버전(스키마 1)은 요청과 처리에서 사용할 수 없게 된다. 배포 뒤 새 프롬프트 버전을 만들어야 리뷰를 요청할 수 있다.
  - 기존 데이터: 저장된 이전 형식의 완료 결과(문자열 피드백)는 새 형식으로 읽을 수 없다. dev에 이미 완료된 결과가 있으면 새 형식으로 읽지 못하므로 배포 전에 정리가 필요하다. prod는 AI 리뷰를 공개하기 전이라 영향이 없다.
