# ADMIN-011 Jev 프롬프트 수동 관리와 제공자 분리

- 결정일: 2026-11-19
- 상태: 확정 · 프롬프트 관리 구현·검증 완료, 미배포
- 변경 전: ai_prompt_versions는 GPT PHOTO_REVIEW 전용으로 버전을 만들면 최신 버전을 곧바로 사용했다.
- 변경 후: 테이블을 유지하며 Jev 분류·사진 검수 역할과 설정 JSON을 추가한다. 관리자가 직접 입력·저장한 새 Jev 버전은 비활성이고 명시적으로 적용해야 활성 버전이 된다. Flyway·서버 시작 시 프롬프트를 자동 생성하지 않는다. GPT의 기존 동작과 조회 계약은 유지한다.
- 변경 이유: 사용자가 초기 프롬프트를 관리자 화면에서 직접 입력하기를 원했고, 실험과 운영 적용을 구분하면서 GPT/Jev 설정이 섞이지 않도록 요청했다. 별도 프롬프트 테이블을 늘리기보다 기존 테이블에 제공자별 형태 제약과 읽기 경계를 둔다.
- 영향 범위: Jev 전용 API·도메인 매핑·모델 검증을 사용한다. 저장과 적용에는 역할별 DB 잠금을 사용하며, 적용할 때는 두 역할을 같은 순서로 잠가 분류 선택지와 사진 규칙의 호환성을 확인한다. 새 버전 내용은 불변이고 운영 활성 상태만 변경한다. 감사 로그는 관리자·역할·버전 또는 활성 버전 ID만 남기며 본문은 복사하지 않는다.
- 관련 규칙: [ADMIN-011](../rules/admin.md#admin-011-ai-프롬프트-버전)
- 관련 이슈·PR: [#1056](https://github.com/woowacourse-teams/2026-Chalkak/issues/1056), PR 미등록

모델은 실험에서 사용한 jev-1.14.0을 명시하고 가변 별칭을 허용하지 않는다. 공급자 요청의 지침·선택지 형식은 [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice), 버전 ID는 [공식 모델 문서](https://docs.typesafe.ai/models)를 확인했다. 이 문서와 설정 기능 구현은 운영 자동 검수나 실제 모델 성능 검증을 완료했다는 의미가 아니다.

저장·적용·버전 번호의 동시성, 감사 저장 실패 시 원자적 롤백, GPT/Jev 조회 분리, 관리자 권한과 OpenAPI 계약을 검증했다. 관련 478개 테스트가 통과했으며 실제 Jev 호출은 다음 개발 단위다.
