# BANNER-001~003 외부 웹페이지를 배너로 등록한다

- 결정일: 2026-10-19
- 상태: 확정
- 변경 전: 서버에 배너를 등록하는 기능과 배너 도메인 규칙이 없었다.
- 변경 후: 관리자가 제목·부제목·웹뷰 URL·썸네일 URL을 등록한다. 네 항목의 공백 제거·길이·HTTPS 주소를 검증하고 웹뷰 URL 전체 문자열의 중복을 거절한다. 등록 감사는 제목·부제목의 SHA-256 해시만 기록하며 URL과 문구 원문을 제외하고 등록과 같은 트랜잭션에서 저장한다.
- 변경 이유: 앱의 배너를 통해 홍보·안내 등 외부 콘텐츠에 접근하도록 정보를 저장한다. 외부 페이지 배포와 서버의 메타데이터 관리를 구분한다. 쿼리 파라미터는 외부 페이지에서 콘텐츠를 구분할 수 있으므로 임의로 제거하지 않는다. 중복 응답은 처음 제안한 409 대신 기존 예외 규칙에 맞춰 400으로 정정하기로 사용자와 합의했다.
- 영향 범위: 관리자 배너 등록 API와 감사 로그. 전체 CRD 중 등록만 이번 커밋에서 구현하며, 관리자 목록 조회·논리 삭제·비로그인 앱 조회는 후속 단위다. 미삭제 배너 간 중복 금지와 삭제 후 재등록 허용은 삭제 단위에서 완성한다. 기존 API 계약은 변경하지 않는다.
- 관련 규칙: BANNER-001, BANNER-002, BANNER-003, ADMIN-001, ADMIN-006, ADMIN-007
- 관련 이슈·PR: [#676](https://github.com/woowacourse-teams/2026-Chalkak/issues/676), 후속 [#677](https://github.com/woowacourse-teams/2026-Chalkak/issues/677)·[#678](https://github.com/woowacourse-teams/2026-Chalkak/issues/678). PR 미등록, 서버 미배포.

## 입력 검증 보완

PR #684 리뷰에서 U+2003으로 둘러싼 정상 입력이 그대로 저장되거나 길이·URL 오류로 거절되는 점과, 65535를 초과한 포트가 허용되는 점을 확인했다. 사용자 승인으로 일반 공백 제거 동작을 유지하면서 Unicode 공백 제거를 추가하고 포트 상한을 검증한다. 잘못된 URL의 메시지는 웹뷰·썸네일 필드를 구분한다. 기존 API 경로·응답 필드·오류 코드와 한글 호스트 허용 범위는 유지한다. 테스트로 오류를 먼저 재현한 뒤 정상 공백·길이·포트 경계를 검증한다.
