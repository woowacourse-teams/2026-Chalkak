# NOTIFICATION-010·NOTIFICATION-011 오늘 주제 참여 상태에 따른 발행·발송 제외

- 결정일: 2026-10-12
- 상태: 확정
- 변경 전: 주제 푸시는 사진 제출 여부와 관계없이 수신 허용 정상 회원에게 발행했다.
- 변경 후: 오늘 주제에 삭제되지 않은 `VALIDATING`·`PENDING`·`APPROVED` 게시물이 있는 회원은 제외한다. `REJECTED`·삭제된 게시물만 있는 회원은 계속 대상에 포함한다. 반려 후 재제출한 승인 대기 게시물이 있으면 제외한다. 게시물 생성 날짜가 아닌 관련 주제 ID로 판정한다.
- 변경 이유: 이미 사진을 제출해 처리 중이거나 검수가 진행·완료된 회원에게 반복 주제 알림을 보내는 피로를 줄인다. 반려·삭제 후에는 다시 참여할 수 있으므로 주제 알림을 유지한다.
- 영향 범위: SQS 발행 대상 조회, Worker 기기별 FCM 요청 전 재검증과 앱·주제 설정 안내. 게시물 작성·재제출 API, 푸시 수신 설정과 30분 발송 기한은 유지한다. `VALIDATING`의 재제출 가능 여부를 판단하는 처리 시간 초과 규칙은 발행 대상 제외 조건으로 가져오지 않는다.
- 관련 규칙: NOTIFICATION-010·NOTIFICATION-011.
- 관련 이슈·PR: [#591](https://github.com/woowacourse-teams/2026-Chalkak/issues/591). PR 미등록.

발행 전에는 대상자를 일괄 조회하며 회원별 추가 조회를 하지 않는다. 큐 등록 이후 제출할 수 있으므로 Worker가 기기별 실제 FCM 요청 전 최신 제출 상태를 다시 확인한다. 기존 `PostRepository.findActiveByAuthorIdAndTopicId`를 재사용하며, 이 조회는 삭제·반려를 제외하고 잠금 없이 게시물을 찾는다. 발행 조회도 동일하게 삭제되지 않고 `REJECTED`가 아닌 게시물의 존재 여부를 확인한다. 현재 네 가지 게시물 상태에서 처리 중·승인 대기·승인을 제외한다는 정책은 유지한다. 기기마다 확인하므로 첫 기기 처리 후 제출했다면 다음 기기의 발송은 생략된다. 기존 완료 결과·SQS 삭제 경로를 재사용하고 별도 재시도는 추가하지 않는다.

DB 확인과 외부 FCM 요청은 하나의 원자적 작업이 아니다. 확인 직후 제출과 발송이 겹치면 이미 시작한 요청까지 막을 수는 없으며, 제출 때문에 수락된 메시지를 회수하지 않는다. 발행·Worker·활성 게시물 유니크 인덱스의 비반려·비삭제 조건을 맞췄다. 새 게시물 상태가 추가되면 그 상태를 활성 게시물로 취급할지 정책과 관련 조회·DB 제약을 함께 검토한다.
