# ADMIN-012 관리자 AI 리뷰 조회 도입

- 결정일: 2026-10-26
- 상태: 확정
- 변경 전: 관리자가 AI 리뷰를 볼 방법이 없었다. 프롬프트 버전별 결과 품질을 확인하려면 DB를 직접 조회해야 했고, AIREVIEW-003은 관리자 조회를 "아직 제공하지 않으며 #691에서 정한다"로 남겨 두었다.
- 변경 후: 관리자가 숨겨진 리뷰를 포함한 모든 AI 리뷰를 상태·프롬프트 버전으로 걸러 마지막 요청 시각 최신순으로 페이지 단위 조회한다. 상세에서는 변환된 결과, 모델의 원출력(완료된 리뷰만), 호출 기록(토큰, 지연시간, OpenAI 응답 ID)을 확인한다. 각 항목에 작성자 앱에서 보이는지(`visibleToAuthor`)를 함께 알리고, 오류 코드는 관리자에게만 보인다. 조회는 감사 로그를 남기지 않는다.
- 변경 이유:
  - 프롬프트 품질 점검에는 숨겨진 리뷰도 필요하다. 게시물이 삭제되거나 작성자가 탈퇴해도 그 리뷰가 만든 결과와 비용은 남아 있고, 이를 걸러 내면 특정 버전의 실패·점수 분포를 왜곡한다. 그래서 사용자 조회의 공개 조건(AIREVIEW-004)을 관리자에게는 적용하지 않는다.
  - 최신순 기준은 최초 요청 시각이 아니라 마지막 요청 시각이다. 실패한 리뷰를 다시 요청하면 같은 행이 새 회차의 프롬프트 버전으로 다시 고정되므로, 마지막 요청 시각이 지금 붙은 프롬프트 버전과 같은 회차를 가리킨다. 최초 요청 시각으로 정렬하면 재요청한 리뷰가 옛 자리에 남아 방금 바꾼 버전의 결과를 찾기 어렵다.
  - 마지막 요청 시각은 다시 요청할 때 바뀌어 페이지를 넘기는 사이 순서가 밀릴 수 있다. 게시물당 요청은 최대 3회이고 관리자 조회도 드물어 커서 방식 대신 규칙에 한계로 남긴다.
  - 숨김 여부는 서버가 계산한 값 하나로 줄이지 않고 게시물 삭제 시각·검수 상태·작성자 상태·삭제 시각의 원값을 그대로 보여 주며 `visibleToAuthor`를 더한다. 원값은 게시물·작성자 쪽 사유를 알려 주고(주제·사진 삭제는 `visibleToAuthor`로만 드러난다), `visibleToAuthor`는 POST-007 조건을 관리자 화면이 따로 구현하지 않아도 되게 한다.
  - 이번에는 정렬·필터용 인덱스를 추가하지 않는다. 리뷰는 게시물당 한 행이라 행 수가 게시물 수 이하로 제한되고 관리자 전용이라 호출이 드물다. 마이그레이션은 공유 테스트 DB와 버전 검사 부담이 있으므로, 느려지면 마지막 요청 시각과 ID 내림차순 인덱스를 추가한다.
  - 원출력은 완료된 리뷰만 보여 준다. 저장소가 원출력을 완료 시점에만 저장하기 때문에 실패·대기·처리 중인 리뷰에는 보여 줄 값이 없다. 실패한 호출의 원본 응답은 기록하지 않는다.
- 영향 범위: 관리자 API 두 개(`GET /api/v1/admin/ai-reviews`, `GET /api/v1/admin/ai-reviews/{aiReviewId}`). 관리자 전용이라 앱(Android·iOS)과 회원 API는 바뀌지 않는다. 관리자 웹 화면은 별도 작업이다. DB 변경과 마이그레이션은 없다. 구현은 `backend/src/main/java/com/chalkak/backend/admin/**/AdminAiReview*`에 있다.
