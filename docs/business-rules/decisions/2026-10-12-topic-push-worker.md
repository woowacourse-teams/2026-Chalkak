# NOTIFICATION-010·011 주제 메시지의 공통 Worker 처리와 직접 발행

- 결정일: 2026-10-12
- 상태: 확정
- 변경 전: 공통 Worker는 승인·반려의 알림함 ID와 DB 알림을 기준으로 발송 조건을 검증했다. 알림함에 저장하지 않는 주제 메시지는 처리할 수 없었다.
- 변경 후: 주제 종류·관련 대상은 `TOPIC`으로 구분하고 알림함 ID 없이 처리한다. 기존 로그인·기기 검증과 FCM 결과·SQS 완료 처리를 재사용하면서, 주제만 정상 회원·주제 수신 설정·KST 오늘 주제의 일치 여부를 확인한다. 현재 기기를 조회하므로 예정 시각 이후 등록한 기기도 포함한다. 제목은 `오늘의 주제`, 본문은 주제명으로 구성한다. 앱은 원래 주제 ID로 날짜를 고정하지 않고 클릭한 날의 오늘 주제를 조회한다.
- 변경 이유: 주제를 알림함·Outbox에 저장하지 않는 합의와 기존 발송 흐름을 함께 유지한다. 승인·반려의 정지 회원 허용 정책을 주제에 적용하지 않고, 독립된 두 수신 설정을 각 종류에 맞게 판단한다. 앱은 없는 알림함 ID로 상세·읽음 API를 호출하지 않아야 한다.
- 영향 범위: 주제 SQS 메시지, 공통 Worker와 FCM 데이터, Android·iOS 표시·클릭 계약. 승인·반려의 기존 메시지 필드와 REST 응답은 유지한다. 새 enum 값은 주제 푸시용이며 주제 알림함 행을 생성하지 않는다.
- 관련 규칙: NOTIFICATION-005, NOTIFICATION-006, NOTIFICATION-008, NOTIFICATION-009, NOTIFICATION-010, NOTIFICATION-011
- 관련 이슈·PR: [#572](https://github.com/woowacourse-teams/2026-Chalkak/issues/572). PR은 아직 등록하지 않았다.

이 기록은 기존 합의의 구현 반영이다. 첫 커밋 `b9d3e4c1`은 SQS 이후의 처리와 계약 및 공통 발송 기한 정책을 구현했다. 다음 변경은 정시 직접 발행·설정 적용 시점을 연결한다. 실제 AWS·Firebase·기기 연동과 서버 배포는 아직 확인하지 않았다. 수락은 기기 수신을 뜻하지 않는다.


## 주제 직접 발행의 처리 경계

정시 실행은 Relay와 별도의 단일 스케줄러에서 관리자 설정을 확인한다. 현재 회차를 시도한 사실만 프로세스 메모리에 남기며 원래 예정 시각부터 30분인 기한은 `PushDeadlinePolicy`를 재사용한다. 설정을 지난 시각으로 바꾸면 오늘 회차를 소급 실행하지 않는다. 대상은 정상 회원·주제 수신 설정으로 조회하고, 게시물 제출 여부를 조회하지 않는다. SQS 외부 요청은 DB 조회 트랜잭션이 끝난 뒤 실행한다.

한 회원의 SQS 오류·결과 불명은 로그와 집계에 남기고 다음 회원을 처리한다. 같은 프로세스에서 해당 회차를 다시 발행하지 않는다. 재시작·배포 중 중복과 발행 도중 중단에 따른 누락을 허용한 기존 Best Effort 합의를 구현하며 이를 전달 보장으로 설명하지 않는다. 조회 실패·주제 없음·대상 없음도 회차 시도로 종료된다. 실행 중인 회차는 설정 삭제로 되돌리지 않고 다음 실행부터 취소한다.

푸시 기한은 승인·반려와 주제 모두 30분이며 계산·검증만 도메인의 정적 정책 클래스로 모은다. 엔티티의 기존 시각 컬럼과 DTO의 `Instant`를 유지하고 기한 값 객체나 이를 위한 주제 엔티티는 추가하지 않는다. SQS 숨김·재시도·알림함 보관과 FCM 형식 변환은 각각의 책임에 유지한다.
