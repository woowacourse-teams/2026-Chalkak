# POST-006·ADMIN-003·NOTIFICATION-001 Jev 승인 추천만 자동 공개

- 결정일: 2026-11-20 (후속 사용자 변경 합의는 2026-11-19)
- 상태: 확정 · 서버 회귀 테스트 1,625개 통과, 미배포
- 변경 전: 이미지 준비 후 관리자가 PENDING을 승인/반려했다. 초기 Jev 설계에는 반려 추천의 자동 반려도 있었지만 구현 전에 사용자가 이를 철회했다.
- 변경 후: 신규 등록과 같은 트랜잭션에 대상/불변 프롬프트 참조를 예약하고, 이미지 준비 후 Jev를 호출한다. 승인 추천만 자동 승인/사용자 알림으로 확정한다. 반려 추천·검토·최종 기술 오류는 PENDING 관리자 확인 대기로 둔다. 원래 추천과 실제 게시물/관리자 결정은 구분한다.
- 변경 이유: 잘못된 반려를 사람이 바로잡을 수 있도록 자동 반려를 없애기로 했다. 등록 때 설정을 고정하여 준비 중 운영 적용이 바뀌거나 자동 검수를 새로 켠 경우 기존 등록이 섞이지 않게 한다.
- 영향 범위: 게시물 등록 이벤트와 기존 PENDING 준비 흐름에 DB 예약을 원자적으로 연결한다. 도입 전 VALIDATING의 완료는 수동 대기로 남긴다. 삭제/선처리/탈퇴/중단 상태에서 새 모델 호출과 늦은 공개/알림을 막는다. 실제 이미지 처리 실패의 기존 REJECTED는 유지한다.
- 중단/교체: 명시 비활성화 revision을 기존 프롬프트 테이블에 남겨 재활성화 후에도 이전 미완료 작업을 보류한다. 단순 버전 교체는 이 revision을 늘리지 않고 이미 선택된 불변 ID를 유지한다. 노드 시계 차이로 중단 경계가 바뀌지 않도록 시각 대신 revision을 비교한다.
- 원자성: 결과 원문 저장과 실제 적용은 분리하되 DB 미적용 행으로 재시작을 복구한다. 자동 승인·적용 기록·사용자 알림은 한 트랜잭션이다. 자동 실행에 가짜 관리자 actor/감사 ID를 만들지 않는다. 공개 후 사람의 정정은 별도 후속 API다.
- DB 선택: 캐시만 쓰면 재시작 시 공유 분류/실행 소유권/시도 횟수/원응답과 사용량이 사라져 재호출 비용과 중복 적용을 통제하기 어렵다. 기존 posts 집계와 두 신규 표만 사용하며 별도 사용자 카운터·outbox 표를 늘리지 않는다. Caffeine 읽기 캐시는 이번 범위에 없다.
