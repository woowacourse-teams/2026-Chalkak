# NOTIFICATION-002~004 알림함 30일 보관 정책

- 결정일: 2026-10-06
- 상태: 확정
- 변경 전: 일반 회원의 알림은 생성 후 60일이 지난 뒤 정리했다. 조회에는 별도 보관 기간 조건이 없어 정리 전에는 오래된 알림도 조회·읽음 처리할 수 있었다.
- 변경 후: 일반·정지 회원의 알림은 사건 발생 시각부터 30일 보관한다. 현재 검수 알림은 검수 확정 시각을 `created_at`에 저장한다. 정확한 30일 경계에는 표시하고, 경계를 넘으면 목록·상세·미읽음·단건 및 전체 읽음에서 제외한다. 다음 정리 작업에서 실제 행을 삭제한다. 읽음 여부로 기간을 연장하지 않는다. 탈퇴 회원은 생성 시각과 관계없이 탈퇴 시각부터 30일이 지난 뒤 남은 알림을 정리한다.
- 변경 이유: 별도 Outbox를 유지하지 않는 변경 설계에서 일반 알림의 보관 기간을 30일로 합의했다. 기존 60일은 당시 Outbox 보관 기간과 맞추기 위한 기준이었다. 주기적 정리 시각 때문에 실제 조회 가능 기간이 달라지지 않도록 조회·읽음에도 같은 경계를 적용한다.
- 영향 범위: 기존 알림함 조회·읽음 API의 제공 기간, 주기적 알림 정리, 앱에서 보관 기간이 지난 알림 ID로 접근할 때의 404 처리. 요청·응답 필드, URI, 상태 코드, 정지·탈퇴 회원의 접근 정책은 유지한다. 이전에 저장된 알림도 새 기준을 적용한다.
- 관련 규칙: NOTIFICATION-002, NOTIFICATION-003, NOTIFICATION-004
- 관련 이슈·PR: [#541](https://github.com/woowacourse-teams/2026-Chalkak/issues/541), [PR #548](https://github.com/woowacourse-teams/2026-Chalkak/pull/548). 운영 서버 반영 여부는 별도로 확인한다.

## 승인 알림의 게시물 화면 이동을 위한 대상 정보

- 변경 전: 목록 응답에는 알림 ID만 있고 게시물 ID가 없어 앱이 승인 알림에서 관련 게시물을 바로 조회할 수 없었다.
- 변경 후: 목록에 `sourceType`·`sourceId`를 추가한다. 현재 승인·반려는 `POST`와 게시물 UUID를 제공한다. 앱은 승인을 게시물 화면으로, 반려를 알림 ID로 조회한 사진·사유 상세 화면으로 연결한다. 반려 상세에는 새로 올리기 버튼을 두지 않는다. 기존 상세 API와 읽음 계약은 유지한다.
- 변경 이유: 사용자와 합의한 종류별 화면 이동을 가능하게 하며 알림 ID와 관련 대상 ID를 구분한다. 응답 필드 추가로 기존 v1 요청·응답 필드를 유지하고 새 API 버전을 만들지 않는다.
- 영향 범위: 알림 목록 응답, Android·iOS 클릭 화면 연결. 앱 화면 구현과 서버 배포는 이번 서버 검증에 포함하지 않는다.
- 관련 규칙·이슈: NOTIFICATION-002, [#541](https://github.com/woowacourse-teams/2026-Chalkak/issues/541)
