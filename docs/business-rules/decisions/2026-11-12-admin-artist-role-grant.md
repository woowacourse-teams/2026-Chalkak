# ADMIN-002·006 관리자 작가 권한 변경

- 결정일: 2026-11-12
- 상태: 확정
- 변경 전: 첫 설계는 관리자에게 작가 권한 부여를 허용했다.
- 변경 후: 관리자는 회원 상세에서 역할을 확인하고, 사유를 남겨 탈퇴하지 않은 회원에게 작가 권한을 부여하거나 회수할 수 있다. 이용 정지 상태는 유지한다. 두 방향의 역할 변경 모두 관리자와 대상, 사유, 변경 전후 역할을 같은 트랜잭션에서 감사 로그에 남긴다. 회수된 회원은 일반 회원의 자격을 충족하면 다시 신청할 수 있다.
- 변경 이유: 운영자가 작가 권한을 직접 부여하고 회수할 수 있도록 한다. MVP에서는 운영상 권한 회수와 본인 신청 자격을 독립적으로 관리한다.
- 역할 저장 방식: Java에서는 `UserRole` enum을 사용한다. DB에서는 `VARCHAR`와 CHECK 제약으로 `USER`·`ARTIST`만 허용한다. PostgreSQL enum 타입을 별도로 추가하지 않아도 DB가 허용 값을 검사할 수 있어 이 방식을 사용한다.
- 영향 범위: 관리자 v1 회원 상세·역할 변경과 감사 로그, 회원 v1 내 정보·작가 신청.
