# POST-005·POST-010 게시물 설명 추가

- 결정일: 2026-11-02
- 상태: 확정
- 변경 전: 게시물에는 선택 제목(최대 10자)만 있었고 별도 설명 필드는 제공하지 않았다. 제목 수정 API는 있었지만 규칙 문서에는 수정 기능이 없다고 적혀 있었다.
- 변경 후: 선택 설명을 추가한다. Unicode code point 기준 최대 300자이며 앞뒤 공백·줄바꿈을 제거하고, 가운데 줄바꿈은 허용해 길이에 포함한다. 작성·수정 때 입력하고 게시물 상세와 관리자 게시물 상세에서 보여준다. 수정은 제목과 설명을 함께 교체하며, 요청에서 설명을 생략하면 설명을 삭제한다. 제목·설명에 NUL 문자(U+0000)가 포함되면 잘못된 요청으로 거절한다.
- 변경 이유: 사진에 짧은 글을 함께 남기고 싶다는 요구사항이다. 관리자가 게시물을 조회할 때 설명도 함께 볼 수 있도록 관리자 상세에 노출한다. 검수 대상은 사진이며 제목·설명은 검수하지 않는다(ADMIN-003). 목록 응답 크기를 유지하기 위해 피드·캘린더·작성자별 목록에는 넣지 않는다.
- 영향 범위: `POST /api/v1/posts`·`PUT /api/v1/posts/{postId}` 요청의 `description`, `GET /api/v1/posts/{postId}`·수정 응답·관리자 게시물 상세 응답의 nullable `description`, `posts.description` 컬럼. 기존 필드와 수정 조건을 유지하는 필드 추가이므로 v1을 유지한다.
- 관련 규칙: POST-005, POST-007, POST-010, ADMIN-003
- 관련 이슈·PR: [#894](https://github.com/woowacourse-teams/2026-Chalkak/issues/894), [#896](https://github.com/woowacourse-teams/2026-Chalkak/pull/896)

## 수정 요청에서 설명을 생략할 때

수정 요청의 `description`을 필수 속성으로 두면 이전 버전 앱의 수정 요청이 모두 400을 받아 강제 업데이트가 필요하다. 생략하면 기존 설명을 유지하는 방식은 "생략"과 "`null`로 삭제"를 구분해야 해 요청 처리가 복잡해지고 제목과 규칙이 달라진다. 이전 버전 앱에서는 설명을 쓸 수 없어 지워질 설명이 없으므로, 생략을 삭제로 처리하는 방식을 선택했다.

같은 계정으로 새 버전 앱에서 설명을 쓰고 이전 버전 앱에서 수정하면 설명이 지워진다. 수정은 주제가 `OPEN`인 동안만 가능하고 이런 사용은 드물어 허용한다.

새 버전 앱끼리도 한 기기가 이전에 불러온 설명으로 수정 요청을 보내면 다른 기기에서 바꾼 설명을 덮어쓴다. 수정은 제목과 설명을 마지막 요청으로 통째로 교체하는 방식이라 버전 확인 없이 일어나는 일이다. 수정은 주제가 `OPEN`인 동안만 가능하고 한 계정이 여러 기기에서 동시에 수정하는 경우는 드물어, 버전 충돌 검사를 추가하지 않고 허용한다.

## 승인 후 수정과 검수

관리자 검수는 사진을 대상으로 하며 제목·설명은 원래 검수 대상이 아니다. 따라서 `APPROVED` 게시물의 제목·설명을 바꿔도 다시 검수하지 않고 검수 상태를 유지한다. 관리자 상세의 설명 노출은 조회 편의를 위한 것이다.

## NUL 문자 거절

PostgreSQL의 문자 타입은 NUL 문자(U+0000)를 저장할 수 없어, NUL이 섞인 제목·설명은 저장 시점에 서버 오류가 됐다. NUL은 공백으로 취급되지 않고 1자로 세어져 기존 검증을 통과했기 때문이다. 입력 실수로 보고 제목·설명 모두 잘못된 요청(400)으로 거절한다. 값이 없는 `null`은 지금처럼 제목 없음·설명 없음으로 허용하며, 줄바꿈 등 다른 문자는 제한하지 않는다.

## 제목 길이 규칙 문구 정정

POST-005는 제목의 앞뒤 공백을 제거하지 않는다고 적혀 있었지만 서버는 앞뒤 공백을 제거한 뒤 길이를 세고 있었다. 설명과 같은 기준으로 통일하면서 문서를 현재 동작에 맞췄다. 제목 처리 방식 자체는 바뀌지 않는다.
