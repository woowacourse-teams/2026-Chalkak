# ADMIN-008 Jev 결과 알림과 DB 재시도

- 결정일: 2026-11-20. 기존 알림 인터뷰 승인과 반려 추천의 관리자 결정 정책을 함께 반영.
- 상태: 관련 서버 테스트 399개 통과, 미배포.
- 문제: 최초 PENDING과 자동 결과를 모두 알리면 관리자가 승인될 사진까지 확인해야 한다. 단발 HTTP 전송은 서버 재시작 시 유실되고 결과 재처리로 모델 비용까지 반복될 수 있다.
- 선택: 운영 검수 이력의 JSONB에 Slack 상태·최대3개 시도/오류 코드를 저장하고 due 인덱스로 재개한다. 외부 전송은 DB 트랜잭션 밖에서, 결과는 발송권 ID가 일치할 때만 반영한다. 추가 알림 테이블은 만들지 않는다.
- 대상: 반려 추천/검토/최종 기술 오류와 꺼짐·미설정 수동 대상만 요약+관리자 링크. 사용자 알림은 실제 승인/반려 규칙 그대로다.
- 재시도: 최초 포함3회, 1분/5분 및 더 긴 Retry-After. 4xx 설정 오류는 중단하고 성공 시 추가 시도를 하지 않는다. 서버 유실/재시작은 만료 리스를 오류 이력에 남기고 이어간다.
- 한계: HTTP 성공 뒤 응답/DB 기록 유실은 외부 중복을 완전히 제거할 수 없다. 같은 시도의 동시 전송 방지와 최대 시도 제한을 제공하되 exactly-once라고 주장하지 않는다. 운영 Slack 실발송은 별도 배포 확인이 필요하다.
