# ADMIN-013 Jev 정답 평가와 실제 판정의 분리

- 결정일: 2026-11-20. 사용자의 관리자 평가·정정 합의와 백엔드 우선/화면 후속 지시를 반영.
- 상태: 확정 · 서버4436개/이미지 Lambda113개 테스트 통과, 미배포.
- 변경 전: 관리자 최초 PENDING 판정과 프롬프트 시험만 있으며 원래 결과에 독립적인 정답/실제 정정 경로가 없었다.
- 변경 후: 기존 검수 행에 현재 정답을 저장하고 기존 감사로 변경 이력을 남긴다. 실제 승인↔반려는 별도 API·양방향 사유·알림으로 처리한다. 평가만 입력해 사진이 공개되거나 알림이 가지 않게 분리했다.
- 이유: 모델의 오승인/오반려를 수집하는 작업과 사용자의 실제 사진 처리 작업은 영향이 다르다. 원래 추천과 당시 운영 처분을 보존해야 정정 후에도 모델의 오류를 지표에서 숨기지 않는다.
- 일관성: 정답+감사, 실제 상태+감사+알림을 각각 원자적으로 저장한다. 회원→게시물 잠금으로 재등록과 이전 반려의 재승인 경합을 막으며 삭제·탈퇴·이미지 실패를 복구하지 않는다. 실제 정정도 평가 정답은 덮어쓰지 않는다.
- 집계: 원문·프롬프트를 전체 로딩하지 않고 필요한 작은 평가/호출 필드만 조회한다. 공유 분류/callId 중복을 제거하며 토큰 결측과 실제 HTTP p99를 구분한다. 기간/건수 상한과 truncated로 불완전한 집계를 알리고 실제 모델 성능으로 과장하지 않는다.
- 검증: 실제 DB 롤백·분류 공유 토큰·대체 게시물 차단과 모델/평가/운영 상태 분리를 확인한다. 운영 AWS/TypeSafe 정확도 검증은 별도이며 관리자 화면은 병합 후다.
