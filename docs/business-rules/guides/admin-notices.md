# 관리자 공지 연동 안내

## 현재 제공 범위

#592에서 공지 등록과 목록·상세 조회 API를, #594에서 예약 시각의 알림함 배포를, #595에서 배포된 공지의 푸시 발송을, #593에서 배포 전 공지의 수정 API를 구현한다. 삭제는 #612에서 추가한다. 배포는 KST 매 분 0초에 확인하므로 즉시 발송도 최대 1분 늦어질 수 있다. 실제 배포와 관리자 클라이언트 연동은 아직 확인하지 않았다. 정책은 [알림 규칙](../rules/notification.md)의 NOTIFICATION-012·013을 따른다.

## 공지 등록

`POST /api/v1/admin/notices`

관리자 액세스 토큰을 `Authorization: Bearer <adminAccessToken>`으로 전달한다. 일반 회원 토큰은 사용할 수 없다.

```json
{
  "title": "서비스 점검 안내",
  "body": "10월 20일 02:00부터 04:00까지 서비스 점검이 진행됩니다.",
  "scheduledAt": "2026-10-19T09:00:00Z"
}
```

- `title`은 필수이며 앞뒤 공백을 제거한 뒤 Unicode code point 기준 1~50자다. 한글·영문·단일 이모지(📢)는 1자지만, 여러 code point를 합친 이모지는 여러 자로 센다(👨‍👩‍👧 5자, 🇰🇷 2자, 피부톤 이모지 2자). 관리자 화면의 글자 수 표시는 `str.length`가 아니라 `[...str].length`처럼 code point 단위로 센다.
- `body`는 필수이며 앞뒤 공백을 제거한 뒤 같은 기준으로 1~500자다.
- `scheduledAt`은 필수이며 시간대가 포함된 ISO-8601 시각(UTC Instant)이다. 즉시 발송하려면 현재 시각을 보낸다. 요청 처리 시각보다 5분 넘게 과거인 값은 거절하고, 정확히 5분 전까지는 허용한다. 미래 시각에는 상한이 없다.
- 본문은 감사 로그에 원문 대신 SHA-256 해시로 남기므로 `password: 8자 이상` 같은 설정값 형식이나 이미지 링크가 있어도 등록된다. 제목은 감사 로그에 그대로 남기므로, 이미지 URL이나 `password: …`·`token=…` 같은 형식이 있으면 거절한다.
- 요청은 공지만 저장한다. 등록 요청 자체는 푸시를 보내지 않는다. 처리 관리자와 제목·예약 시각·본문 해시를 감사 로그에 남기며, 감사 기록이 실패하면 공지도 저장하지 않는다.

성공은 `201`이며 저장된 공지를 반환한다. `title`·`body`는 앞뒤 공백을 제거한 값이다. 모든 시각은 UTC Instant다. `status`는 회원 알림함 배포 상태로 등록 직후에는 `SCHEDULED`이고, 예약 시각이 지나 알림함에 배포되면 `DISTRIBUTED`가 된다. `distributedAt`은 배포한 시각이며 배포 전에는 `null`이다.

```json
{
  "noticeId": "019a0000-0000-7000-8000-000000000592",
  "title": "서비스 점검 안내",
  "body": "10월 20일 02:00부터 04:00까지 서비스 점검이 진행됩니다.",
  "scheduledAt": "2026-10-19T09:00:00Z",
  "status": "SCHEDULED",
  "distributedAt": null,
  "createdAt": "2026-10-12T09:00:00Z",
  "updatedAt": "2026-10-12T09:00:00Z"
}
```

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 필수 값 누락·공백, 제목·본문 길이 초과, 5분 넘게 과거인 예약 시각, 제목의 민감 정보 형식 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |

## 공지 목록 조회

`GET /api/v1/admin/notices?page=1&pageSize=20`

관리자 액세스 토큰을 전달한다. 등록한 공지를 등록 최신순(같은 시각이면 ID 역순)으로 조회한다.

- `page`는 1부터 시작하며 기본값은 1이다. `pageSize`는 1~100이며 기본값은 20이다. 범위를 벗어나면 `400 BUSINESS_ERROR`다.
- 전체 개수는 제공하지 않고 다음 페이지 존재 여부(`hasNext`)만 제공한다.
- 공지가 없으면 `200`과 빈 `notices` 배열을 반환한다.

```json
{
  "currentPage": 1,
  "pageSize": 20,
  "hasNext": false,
  "notices": [
    {
      "noticeId": "019a0000-0000-7000-8000-000000000592",
      "title": "서비스 점검 안내",
      "body": "10월 20일 02:00부터 04:00까지 서비스 점검이 진행됩니다.",
      "scheduledAt": "2026-10-19T09:00:00Z",
      "status": "DISTRIBUTED",
      "distributedAt": "2026-10-19T09:00:00Z",
      "createdAt": "2026-10-12T09:00:00Z",
      "updatedAt": "2026-10-12T09:00:00Z"
    }
  ]
}
```

항목 필드는 등록 응답과 같다. 삭제 여부는 #612에서 해당 기능과 함께 응답에 추가한다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 페이지 조건 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |

## 공지 상세 조회

`GET /api/v1/admin/notices/{noticeId}`

관리자 액세스 토큰과 공지 UUID를 전달한다. 성공은 `200`이며 등록 응답과 같은 필드를 반환한다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 UUID |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |
| 404 | BUSINESS_ERROR | 해당 공지가 없음 |

## 공지 수정

`PUT /api/v1/admin/notices/{noticeId}`

관리자 액세스 토큰과 공지 UUID를 전달한다. 본문은 등록과 같은 형식이며, 바꾸지 않는 값도 현재 값으로 함께 보낸다.

```json
{
  "title": "서비스 점검 일정 변경",
  "body": "10월 21일 02:00부터 04:00까지 서비스 점검이 진행됩니다.",
  "scheduledAt": "2026-10-20T09:00:00Z"
}
```

- 검증 기준은 등록과 같다. 제목·본문은 앞뒤 공백을 제거해 저장하고, 예약 시각은 요청 처리 시각보다 5분 넘게 과거면 거절한다. 예약 시각이 지났지만 아직 배포되지 않은 공지는 새 예약 시각을 보내야 한다.
- 배포 전(`status = SCHEDULED`) 공지만 수정할 수 있다. 배포된 공지는 `400`으로 거절한다. 수정 화면 진입 시점과 저장 시점 사이에 배포될 수 있으므로 저장 실패 시 상세를 다시 조회해 상태를 보여 준다.
- 배포와 동시에 요청되면 서버가 공지를 잠가 순서를 정한다. 배포가 먼저 끝났으면 수정을 거절하고, 수정이 먼저면 다음 배포 확인 때 수정된 내용으로 배포한다.
- 수정에는 사유를 받지 않는다. 처리 관리자와 변경 전후의 제목·예약 시각·본문 해시를 감사 로그에 남기며, 감사 기록이 실패하면 수정도 반영하지 않는다. 제목의 민감 정보 형식은 등록과 같이 거절한다.
- 같은 내용으로 저장하면 변경 없이 현재 공지를 `200`으로 반환하고 감사 로그를 추가하지 않는다. `updatedAt`도 바뀌지 않는다.

성공은 `200`이며 등록 응답과 같은 필드로 수정된 공지를 반환한다. 수정하면 `updatedAt`이 수정 시각으로 바뀐다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 UUID, 필수 값 누락·공백, 제목·본문 길이 초과, 5분 넘게 과거인 예약 시각, 제목의 민감 정보 형식, 배포된 공지 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |
| 404 | BUSINESS_ERROR | 해당 공지가 없음 |

## 운영 주의

- 공지는 전용 수신 설정 없이 전체 회원에게 보낸다. 수신 거부 수단이 없으므로 광고성 정보를 넣지 않는다.
- 공지별 발송 결과는 관리자 API로 제공하지 않는다. 공지 ID가 푸시 메시지의 `eventId`이므로 CloudWatch Logs Insights에서 `eventId = 공지 ID`로 조회한다. 조회 방법은 백엔드의 알림 실패 조사 문서를 따른다.
