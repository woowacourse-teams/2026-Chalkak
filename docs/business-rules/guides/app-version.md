# 앱 최소 지원 버전 조회 연동 안내

현재 정책은 [앱 최소 지원 버전 규칙](../rules/app-version.md)을 따른다.

## 로그인 전에 플랫폼 설정 조회

인증 헤더 없이 다음 API를 호출한다. `platform`은 필수이며 `ANDROID` 또는 `IOS`이다. 누락·빈 값·다른 값은 400과 기존 공통 오류 형식이다.

```http
GET /api/v1/app-version?platform=ANDROID
```

설정된 응답 예시이며, 아래 값은 운영 초기값이 아니다.

```json
{
  "platform": "ANDROID",
  "minimumSupportedVersion": "1.2.0",
  "storeUrl": "https://play.google.com/store/apps/details?id=com.example.chalkak"
}
```

두 값은 관리자가 입력·수정한다. 조회는 현재 DB 설정을 읽고 응답을 캐시하지 않는다. 관리자 최초 저장·수정 API와 화면은 후속 #848 및 관리자 웹 작업이다.

## 설정 전에는 업데이트 제한 없이 이용

아직 입력하지 않은 플랫폼도 200이다. 두 필드는 생략하지 않고 모두 null이다.

```json
{
  "platform": "IOS",
  "minimumSupportedVersion": null,
  "storeUrl": null
}
```

이 정상 응답에서는 앱 진입을 허용하고 버전 파싱·스토어 이동을 시도하지 않는다. Android만 설정됐어도 iOS에 Android 설정을 대신 사용하지 않는다.

## 설정된 버전과 비교

`major.minor.patch`의 각 정수를 앞에서부터 비교한다. 문자열 전체나 소수로 비교하지 않는다.

| 현재 버전 | 최소 버전 | 앱 동작 |
| --- | --- | --- |
| `1.9.0` | `1.10.0` | 진입 제한·업데이트 안내 |
| `1.10.0` | `1.10.0` | 정상 이용 |
| `1.10.1` | `1.10.0` | 정상 이용 |

미달이면 업데이트 버튼에서 응답의 `storeUrl`을 연다. 비교·안내 화면·스토어 이동은 앱에서 구현한다. 이 연동이 없는 이전 앱은 서버 설정만으로 진입을 막을 수 없다.

## 통신 실패와 호출 시점

네트워크·서버 오류와 정상 미설정 응답은 구분한다. 통신 실패 시 마지막 설정을 사용할지, 저장된 설정도 없으면 어떻게 진입할지는 미확정이다. 앱 시작·포그라운드 복귀 등 호출 시점과 주기도 연동 전에 합의한다. 미설정 이용 허용을 모든 오류의 이용 허용으로 확장하지 않는다.
