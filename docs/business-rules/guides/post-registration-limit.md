# 게시물 하루 등록 한도 연동 안내

관련 규칙: [POST-003](../rules/post.md#post-003-주제별-게시물-수). #1056 첫 구현 단위이며 커밋·PR·서버 배포 전이다. Android 코드는 이번 작업에서 변경하지 않는다.

## 등록·삭제 전에 잔여 횟수를 확인한다

인증된 회원은 `GET /api/v1/posts/registration-limit`로 본인의 한도를 조회한다. 정지 회원도 조회할 수 있지만 사진 등록 권한이 생기는 것은 아니다. 탈퇴·미인증 회원은 접근할 수 없다. 참여 중인 주제가 없어도 조회할 수 있다.

```json
{
  "limit": 10,
  "usedCount": 3,
  "remainingCount": 7,
  "resetsAt": "2026-11-19T15:00:00Z"
}
```

`resetsAt`은 다음 KST 자정을 나타내는 UTC Instant다. 예시 시각은 한국 시간 2026-11-20 00:00이다. 앱은 표시할 때만 현지 시간으로 변환한다. 횟수 기준은 주제 날짜가 아닌 KST 등록 날짜이며 삭제·반려·생성 후 이미지 처리 실패도 포함한다. 이전 정책의 기록이 10회를 넘으면 usedCount는 실제 수, remainingCount는 0이다.

삭제 확인창에는 다음 내용을 보여준다. 문구의 잔여 횟수는 조회 응답으로 채운다.

> 삭제해도 오늘 등록 횟수는 복구되지 않아요. 오늘 남은 등록 횟수는 7회예요.

남은 횟수가 0이면 다음 초기화 시각을 함께 안내한다. 삭제 자체를 이 한도 때문에 막지는 않는다. 기존 PENDING·APPROVED 삭제 허용과 VALIDATING·REJECTED 삭제 제한은 유지한다.

## 조회한 횟수는 등록 예약이 아니다

업로드 URL 발급은 횟수를 소비하지 않는다. 발급받은 URL이 있어도 게시물 생성 때 한도를 다시 확인한다. 회원별로 동시에 생성해도 하루에 성공한 건은 최대 10개다. 생성 전 실패·롤백은 소비하지 않으며 생성 성공 후 삭제·반려돼도 돌려주지 않는다. 제목·설명 수정과 서버 검수 재시도는 횟수를 추가 사용하지 않는다.

한도에 도달한 `POST /api/v1/posts`는 HTTP 400과 다음 기존 형식의 오류를 반환한다.

```json
{
  "errorCode": "POST_REGISTRATION_LIMIT_REACHED",
  "message": "사진은 하루에 총 10회까지 등록할 수 있습니다. 다음 날 다시 등록해 주세요."
}
```

앱은 오류 코드로 분기해 등록 흐름을 중단하고 잔여 횟수와 초기화 시각을 다시 조회한다. 같은 요청을 즉시 반복하지 않는다. 생성 성공·삭제·반려 뒤 재등록 진입과 앱이 다음 날짜에 활성화될 때 사용량을 다시 조회한다.

기존 `GET /api/v1/posts/today`의 isPosted·postId·moderationStatus와 의미는 바꾸지 않는다. 그 응답은 현재 주제의 활성 슬롯을 나타낸다. remainingCount가 남아 있어도 이미 활성 게시물이 있거나 참여 기간이 끝났으면 새로 작성할 수 없다. 반대로 isPosted가 false여도 일일 한도가 0이면 등록할 수 없다.

## Android 전달 문구

POST-003에 최초 포함 KST 하루 총 10회 등록 제한을 추가했습니다. 삭제·반려해도 횟수는 복구되지 않습니다. `GET /api/v1/posts/registration-limit`의 remainingCount·resetsAt으로 삭제 전 고지와 등록 가능 횟수를 표시하고, 생성 오류 `POST_REGISTRATION_LIMIT_REACHED`에서는 반복 요청 대신 초기화 안내를 보여주세요. 기존 today 응답과 사진 수정 불가 정책은 유지됩니다. 현재 구현·검증 중이며 PR 미등록·서버 미배포입니다. 공통 하네스 새 배포 버전과 실제 서버 반영 여부는 아직 확인되지 않았습니다.
