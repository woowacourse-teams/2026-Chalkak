# 관리자 리마인더 연동 안내

## 현재 제공 범위

#724에서 리마인더 등록·목록 조회·수정·삭제 API를, #726에서 예정 시각의 대상 선정과 푸시 발송을 구현한다. 발송은 서버 설정(`NOTIFICATION_REMINDER_ENABLED`)이 켜진 환경에서만 동작한다. 실제 배포와 관리자 클라이언트 연동, 기기 수신은 아직 확인하지 않았다. 정책은 [알림 규칙](../rules/notification.md)의 NOTIFICATION-014(관리)·015(발송)를 따른다.

리마인더는 관리자가 문구·일정·대상을 정해 보내는 참여 유도 푸시다. 공지와 달리 회원 알림함에 남지 않는다.

| | 관리자 공지 | 리마인더 |
| --- | --- | --- |
| 목적 | 꼭 알려야 하는 정보(점검, 정책 변경) | 참여 유도, 알림 |
| 수신 거부 | 불가 | 회원의 주제 푸시 수신 설정으로 끌 수 있음 |
| 알림함 | 30일 보관 | 남기지 않음 |
| 일정 | 일회성 예약 | 일회성 또는 매일 반복 |
| 대상 | 탈퇴하지 않은 전체 회원 | 전체, 오늘 주제 참여자, 오늘 주제 미참여자 |

## 리마인더 등록

`POST /api/v1/admin/reminders`

관리자 액세스 토큰을 `Authorization: Bearer <adminAccessToken>`으로 전달한다. 일반 회원 토큰은 사용할 수 없다.

```json
{
  "title": "오늘이 얼마 남지 않았어요",
  "body": "사진을 자랑해 주세요!",
  "repeat": "DAILY",
  "target": "TOPIC_NON_PARTICIPANTS",
  "scheduledAt": "2026-10-25T12:00:00Z"
}
```

- `title`은 필수이며 앞뒤 공백을 제거한 뒤 Unicode code point 기준 1~50자다. 글자 수는 공지와 같이 `[...str].length`처럼 code point 단위로 센다.
- `body`는 필수이며 앞뒤 공백을 제거한 뒤 같은 기준으로 1~500자다.
- `repeat`는 필수이며 `ONCE`(일회성) 또는 `DAILY`(매일 반복)다.
- `target`은 필수이며 `ALL`(전체), `TOPIC_PARTICIPANTS`(오늘 주제 참여자), `TOPIC_NON_PARTICIPANTS`(오늘 주제 미참여자) 중 하나다.
- `scheduledAt`은 필수이며 시간대가 포함된 ISO-8601 시각(UTC Instant)이다.
  - `ONCE`: 이 시각에 한 번 보낸다.
  - `DAILY`: 이 시각의 날짜부터 매일 같은 KST 시각에 보낸다. 예를 들어 `2026-10-25T12:00:00Z`(KST 21:00)는 10월 25일부터 매일 KST 21:00이다.
  - 요청 처리 시각보다 5분 넘게 과거인 값은 거절하고, 정확히 5분 전까지는 허용한다. 미래 시각에는 상한이 없다.
- 하루 발송 횟수와 발송 시각대에는 제한이 없다.
- 본문은 감사 로그에 원문 대신 SHA-256 해시로 남기므로 설정값 형식이나 이미지 링크가 있어도 등록된다. 제목은 감사 로그에 그대로 남기므로, 이미지 URL이나 `password: …`·`token=…` 같은 형식이 있으면 거절한다.
- 요청은 리마인더만 저장한다. 등록 요청 자체는 푸시를 보내지 않는다. 처리 관리자와 제목·본문 해시·반복 방식·대상·발송 시각을 감사 로그에 남기며, 감사 기록이 실패하면 리마인더도 저장하지 않는다.

성공은 `201`이며 저장된 리마인더를 반환한다. `title`·`body`는 앞뒤 공백을 제거한 값이다. 모든 시각은 UTC Instant다.

```json
{
  "reminderId": "019a0000-0000-7000-8000-000000000724",
  "title": "오늘이 얼마 남지 않았어요",
  "body": "사진을 자랑해 주세요!",
  "repeat": "DAILY",
  "target": "TOPIC_NON_PARTICIPANTS",
  "scheduledAt": "2026-10-25T12:00:00Z",
  "createdAt": "2026-10-21T09:00:00Z",
  "updatedAt": "2026-10-21T09:00:00Z"
}
```

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 필수 값 누락·공백, 제목·본문 길이 초과, 없는 `repeat`·`target` 값, 5분 넘게 과거인 발송 시각, 제목의 민감 정보 형식 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |

## 리마인더 목록 조회

`GET /api/v1/admin/reminders?page=1&pageSize=20`

관리자 액세스 토큰을 전달한다. 삭제하지 않은 리마인더를 등록 최신순(같은 시각이면 ID 역순)으로 조회한다.

- `page`는 1부터 시작하며 기본값은 1이다. `pageSize`는 1~100이며 기본값은 20이다. 범위를 벗어나면 `400 BUSINESS_ERROR`다.
- 전체 개수는 제공하지 않고 다음 페이지 존재 여부(`hasNext`)만 제공한다.
- 리마인더가 없으면 `200`과 빈 `reminders` 배열을 반환한다.
- 삭제한 리마인더는 목록에 나오지 않는다.

```json
{
  "currentPage": 1,
  "pageSize": 20,
  "hasNext": false,
  "reminders": [
    {
      "reminderId": "019a0000-0000-7000-8000-000000000724",
      "title": "오늘이 얼마 남지 않았어요",
      "body": "사진을 자랑해 주세요!",
      "repeat": "DAILY",
      "target": "TOPIC_NON_PARTICIPANTS",
      "scheduledAt": "2026-10-25T12:00:00Z",
      "createdAt": "2026-10-21T09:00:00Z",
      "updatedAt": "2026-10-21T09:00:00Z"
    }
  ]
}
```

항목 필드는 등록 응답과 같다. 일회성 리마인더가 이미 발송 시각을 지났는지는 별도 필드 없이 `scheduledAt`과 현재 시각으로 판단한다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 페이지 조건 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |

## 리마인더 수정

`PUT /api/v1/admin/reminders/{reminderId}`

관리자 액세스 토큰과 리마인더 UUID를 전달한다. 본문은 등록과 같은 형식이며, 바꾸지 않는 값도 현재 값으로 함께 보낸다.

- 검증 기준은 등록과 같다.
- **일회성(`ONCE`)은 발송 시각 전에만 수정할 수 있다.** 발송 시각 정각부터는 `400`으로 거절하며 삭제만 할 수 있다. 현재 시각이나 5분 이내의 과거 시각으로 등록한 일회성은 등록 직후부터 수정할 수 없으므로, 관리자 화면에서 수정 버튼을 숨기거나 삭제만 안내한다. 수정 화면 진입과 저장 사이에 발송 시각이 지날 수 있으므로 저장 실패 시 목록을 다시 조회해 보여 준다.
- **매일 반복(`DAILY`)은 언제든 수정할 수 있다.** 수정 이후에 오는 회차부터 바뀐 내용이 적용된다.
- 과거 시각 검증은 `scheduledAt`이나 `repeat`를 바꿀 때만 한다. 이미 시작한 매일 반복의 제목·본문·대상만 고칠 때는 현재 `scheduledAt`(과거 시각)을 그대로 보내면 된다. 시각이나 반복 방식을 바꾸려면 새 `scheduledAt`이 요청 처리 시각보다 5분 넘게 과거가 아니어야 한다.
- 수정에는 사유를 받지 않는다. 처리 관리자와 변경 전후의 제목·본문 해시·반복 방식·대상·발송 시각을 감사 로그에 남기며, 감사 기록이 실패하면 수정도 반영하지 않는다.
- 같은 내용으로 저장하면 변경 없이 현재 리마인더를 `200`으로 반환하고 감사 로그를 추가하지 않는다. `updatedAt`도 바뀌지 않는다.
- 삭제된 리마인더는 수정할 수 없다(`400`).

성공은 `200`이며 등록 응답과 같은 필드로 수정된 리마인더를 반환한다. 수정하면 `updatedAt`이 수정 시각으로 바뀐다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 UUID, 필수 값 누락·공백, 제목·본문 길이 초과, 없는 `repeat`·`target` 값, 바꾼 발송 시각이 5분 넘게 과거, 발송 시각이 지난 일회성, 삭제된 리마인더, 제목의 민감 정보 형식 |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |
| 404 | BUSINESS_ERROR | 해당 리마인더가 없음 |

## 리마인더 삭제

`DELETE /api/v1/admin/reminders/{reminderId}`

관리자 액세스 토큰과 리마인더 UUID를 전달한다. 요청 본문과 사유는 받지 않는다.

- 삭제한 리마인더는 목록에서 빠지고, 아직 실행하지 않은 회차는 보내지 않는다. 이미 기기에 표시된 푸시는 회수하지 않는다.
- 이미 삭제한 리마인더를 다시 삭제하면 최초 삭제 시각을 유지하고 `204`로 응답하며 감사 로그를 추가하지 않는다.
- 처리 관리자와 삭제 전후 상태(제목·본문 해시·반복 방식·대상·발송 시각·삭제 시각)를 감사 로그에 남기며, 감사 기록이 실패하면 삭제도 반영하지 않는다.
- 삭제를 되돌리는 API는 없다.

성공은 본문 없는 `204`다.

| 상태 | 오류 코드 | 의미 |
| --- | --- | --- |
| 400 | BUSINESS_ERROR | 잘못된 UUID |
| 401 | UNAUTHORIZED | 관리자 액세스 토큰이 없거나 유효하지 않음 |
| 403 | FORBIDDEN | 관리자 권한 없음 |
| 404 | BUSINESS_ERROR | 해당 리마인더가 없음 |

## 발송 동작

관리자 클라이언트가 호출할 API는 없다. 서버가 매 분 0초(KST)에 확인해 보낸다.

- **보내는 시각:** 일회성은 `scheduledAt`, 매일 반복은 시작일부터 매일 같은 KST 시각이다. 그 시각부터 30분 안에서만 보내며, 30분이 지난 회차나 자정을 넘긴 전날 회차는 보내지 않는다. 서버 발송이 꺼져 있던 동안 지나간 회차도 다시 보내지 않는다.
- **받는 회원:** 탈퇴하지 않은 정상 회원(정지 제외) 중 주제 푸시 수신을 켠 회원이다.

| 대상 | 받는 회원 | 회차 날짜의 주제가 없으면 |
| --- | --- | --- |
| `ALL` | 위 조건의 모든 회원 | 관계없이 보냄 |
| `TOPIC_PARTICIPANTS` | 그 날짜 주제에 반려·삭제되지 않은 사진을 올린 회원 | 보내지 않음 |
| `TOPIC_NON_PARTICIPANTS` | 그 날짜 주제에 반려·삭제되지 않은 사진이 없는 회원 | 보내지 않음 |

- 참여자·미참여자 대상은 주제의 참여 시간이 끝난 뒤에도 보낸다.
- **보내기 직전 다시 확인:** 서버는 회원별로 큐에 넣은 뒤 기기마다 보내기 직전에 다시 확인한다. 그 사이 정지·탈퇴했거나, 수신을 껐거나, 리마인더가 삭제됐거나, 대상 조건이 바뀐 회원(미참여자 대상인데 그 사이 사진을 올린 경우 등)에게는 보내지 않는다.
- **발송 무렵 수정·삭제:** 제목·본문은 보내기 직전의 리마인더에서 읽는다. 발송 무렵 문구를 고치면 고친 문구로, 삭제하면 아직 보내지 않은 회원에게는 보내지 않는다. 이미 기기에 표시된 푸시는 회수하지 않는다. 발송 시각에 수정·삭제 요청이 겹치면 서버는 그 분의 발송을 건너뛰고 1분 뒤 다시 확인한다.
- **같은 날 한 번 더:** 이미 오늘 회차를 보낸 매일 반복의 시각을 오늘의 다른 시각으로 바꾸면, 바뀐 시각에 그날 한 번 더 보낸다. 내일부터 바꾸려면 `scheduledAt`의 날짜를 내일로 지정한다.
- **중복·누락:** 서버 재시작과 겹치면 같은 회차가 두 번 갈 수 있고, 발송 도중 오류가 나면 일부 회원에게 가지 않을 수 있다.
- **발송 결과:** 리마인더별 발송 수는 관리자 API로 제공하지 않는다. 서버 조사 로그에서 리마인더 ID로 확인한다.
- **회원 화면:** 푸시를 누르면 앱 메인 화면이 열린다. 알림함에는 남지 않는다.

## 운영 주의

- 발송 횟수와 시각대를 서버가 제한하지 않는다. 참여 유도 내용을 야간(21시~다음 날 8시)에 보내면 광고성 정보의 야간 전송 규정에 해당할 수 있으므로 등록 전에 발송 시각을 확인한다.
- 참여자·미참여자 대상도 주제의 참여 시간이 끝난 뒤 보낸다. 마감 시각 이후로 예약할 때는 "사진을 올려 주세요" 같은 문구가 올릴 수 없는 회원에게 가지 않는지 확인한다.
- 같은 대상에게 여러 리마인더가 겹치면 회원이 짧은 시간에 여러 푸시를 받는다. 일정이 겹치지 않는지 목록에서 확인한다.
