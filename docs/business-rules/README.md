# Chalkak 비즈니스 규칙

백엔드·Android·iOS가 함께 사용하는 서비스 정책의 현재 상태를 관리한다. Git의 Markdown이 원본이며 Notion은 사용자가 수동 반영하는 팀 공유본이다.

## 등록 기준

- 최초 정리에서는 기존 Notion 규칙과 서버 동작을 대조했다. 이후에는 Git의 현재 규칙, 사용자가 제공한 합의와 현재 코드를 대조하며 Notion을 직접 조회하지 않는다.
- 현재 동작의 문서 누락은 코드 근거로 보완한다. 합의와 구현이 충돌하면 확인하고, 신규 정책을 확정하거나 정책을 바꿀 때는 구현·규칙·결정 기록을 함께 남긴다.
- `의논 필요`, `MVP 제외`로 표시됐거나 아직 제공하지 않는 기능은 활성 규칙에 포함하지 않는다.

## 구조

- `rules/`: 도메인별 현재 규칙
- `decisions/`: 정책이 바뀐 이유와 영향
- `notion-map.yml`: 수동 반영 위치와 규칙 ID
- `NOTION_SYNC.md`: PR 등록 뒤 수동 반영 안내

## 읽는 방법

1. 아래 목차에서 작업과 관련된 `활성` 규칙만 읽는다.
2. 변경 배경이 필요할 때만 현재 규칙에 연결된 결정 기록을 읽는다.
3. `미등록` 문서와 템플릿은 규칙으로 해석하지 않는다.

## 현재 규칙

| 도메인 | 문서 | 상태 |
| --- | --- | --- |
| 회원 | [user.md](rules/user.md) | 활성 |
| 게시물 | [post.md](rules/post.md) | 활성 |
| 주제 | [topic.md](rules/topic.md) | 활성 |
| 사인 | [sign.md](rules/sign.md) | 활성 |
| 좋아요 | [like.md](rules/like.md) | 활성 |
| 관리자 | [admin.md](rules/admin.md) | 활성 |

새 도메인 문서는 [규칙 템플릿](rules/_template.md)을 복사해 만든다. 템플릿은 이후 규칙도 같은 형식으로 기록하기 위해 유지하며 현재 규칙이나 Notion 동기화 대상으로 보지 않는다.

## 변경 이유

정책의 의미가 달라진 결정만 `decisions/`에 남긴다. 작성 형식은 [결정 템플릿](decisions/_template.md)을 따른다. 템플릿은 이후 변경 이유를 같은 형식으로 남기기 위해 유지하며 결정 기록이나 Notion 동기화 대상으로 보지 않는다. Git 이력으로 충분한 오탈자·표현 수정은 별도 기록하지 않는다.

## 검토와 공유

- [수동 반영 위치](notion-map.yml): URL 없이 도메인·페이지 이름·규칙 ID로 안내
- [수동 반영 절차](NOTION_SYNC.md): 작업 종료 시 변경된 현재 규칙의 Notion 반영 방법 안내
- Notion에는 현재 규칙만 반영한다. 결정 기록은 Git에만 둔다. 화면 제어·MCP 연결·자동 갱신은 사용하지 않는다.
