# client-flow

다섯 단계를 순서대로 진행한다. 각 단계는 같은 이름의 커맨드 스킬을 읽고 그대로 따른다.
시작 전에 [공통 약속](references/conventions.md)을 읽는다.

| 단계 | 따를 스킬 | 사람 확인 |
|---|---|---|
| 1 이슈 | `client-issue` | 없음 |
| 2 계획 | `client-plan` | **계획 승인** |
| 3 검증 | `client-tdd` | 막혔을 때만 |
| 4 문서 작성 | `client-record` | 없음(push 확인에서 같이 봄) |
| 5 PR | `client-pr` | **push 확인**, **PR 리뷰** |

스킬 파일은 `client/.agents/skills/<이름>/SKILL.md`에 있다.

## 시작점

- 인자가 `#번호`면 이슈가 이미 있다. 1단계를 건너뛰고 아래 "이어 가기"로 시작할 단계를 정한다. 그 전에 그 이슈의 브랜치에 있는지 본다.
  - 지금 브랜치 이름에 `#번호-`가 있으면 그대로 한다.
  - 없으면 그 이슈의 브랜치를 찾는다. `gh issue develop <번호> --list`(연결된 브랜치)와 `git fetch origin && git branch -a --list '*#<번호>-*'`(연결 안 된 브랜치)를 본다. 찾으면 `git switch <브랜치>`로 바꾼다.
  - 하나도 없으면 `client-issue` 5단계대로 연결 브랜치를 만든다.
  - 브랜치를 바꾸기 전에 커밋하지 않은 변경이 있으면 알리고 멈춘다.
- 인자가 한 줄 설명이면 1단계부터 한다.
- 인자가 없으면 대화에서 무엇을 할지 묻는다. 질문은 선택지 1~3개로 줄인다.

## 이어 가기

세션이 끊겨 다시 불렸을 수 있다. 처음부터 하지 않고, 남은 기록을 **뒤 단계부터** 확인해 처음 걸리는 곳에서 이어 간다.

| 남은 기록 | 이어 갈 곳 |
|---|---|
| 이 브랜치의 PR이 열려 있음 (`gh pr list --head <브랜치>`) | 5단계. `client-pr`의 "리뷰에서 지적받았을 때" |
| `$EVID/evidence.md`에 바꾼 플랫폼 **모두**의 전체 검사 종료 코드 0이 있음 | 화면 확인 대상이고 그 플랫폼의 `$EVID/media/<플랫폼>-after-*`가 없으면 수정 후 화면 확인, 아니면 4단계 |
| 이슈에 `<!-- client-plan -->` 댓글이 있음 | 3단계. 플랫폼마다 `evidence.md`에 Green이 없는 첫 TC부터(Android를 먼저 끝낸다). 화면 확인 대상인데 `<플랫폼>-before-*`가 없고 아직 코드를 고치지 않았으면 수정 전 확인부터 |
| 계획 댓글이 없음 | 2단계 |

- `$EVID`는 [공통 약속](references/conventions.md)의 작업 기록 폴더다.
- 시작하기 전에 한 줄로 알린다. 예: `이어 가기: 3단계 TC 3/5부터 (계획 댓글, evidence.md 기준)`
- 기록끼리 맞지 않으면(예: 전체 검사 통과 기록 뒤에 코드가 또 바뀜) 앞 단계로 돌아간다. 이 경우는 전체 검사다.
- 이미 코드를 고쳤는데 수정 전 캡처가 없으면 수정 전 확인은 건너뛰고, PR의 📸 칸에 "수정 전 캡처 없음(세션이 끊긴 뒤 이어 감)"이라고 적는다.
- 어디서 이어 갈지 판단할 수 없으면 찾은 기록을 보여 주고 한 번만 묻는다.

## 진행 규칙

- 사람 확인 지점에서는 같은 대화에서 묻고, 답을 받으면 다음 단계로 이어 간다.
- 확인 지점 사이에서는 묻지 않는다. 멈추는 경우는 공통 약속의 "사람이 확인하는 곳"에 있는 것뿐이다.
- 단계가 끝날 때마다 한 줄로 알린다. 예: `2 계획 승인됨 → 3 검증 시작 (TC 3개, 화면 확인 대상)`
- 되돌아가는 길:
  - TDD 중 TC가 틀렸으면 2단계 승인으로 돌아간다. 승인받으면 하던 TC의 Red부터 다시 한다.
  - push 확인이나 리뷰에서 고칠 곳이 나오면 고친 뒤 전체 검사 → 수정 후 화면 확인 → 문서 다시 보기를 거쳐 같은 PR에 추가 커밋한다.
- 보류하면 여기서 멈춘다. 만든 이슈를 닫을지, 커밋 없는 연결 브랜치를 원격에서 지울지는 사람에게 묻는다.
- Web 작업은 3단계(검증)를 건너뛴다.
