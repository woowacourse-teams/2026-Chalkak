# 원격 설정 (Firebase Remote Config)

스토어 배포 없이 기능을 끄거나 값을 바꾸기 위한 설정이다.

## 키

| 키 | 타입 | 앱 기본값 | 꺼졌을 때 동작 |
|---|---|---|---|
| `ai_review_enabled` | Boolean | `true` | 홈·피드에서 AI 리뷰 영역을 숨기고 리뷰 조회·요청을 보내지 않는다 |
| `photo_edit_enabled` | Boolean | `true` | 사진을 고르면 편집 화면 없이 원본을 바로 고르고, 사진을 눌러도 편집 화면을 열지 않는다 |

- 기본값은 `domain/model/AppConfig.kt` 한 곳에만 둔다. 콘솔의 기본값과 다를 수 있으므로 앱은 콘솔 기본값에 의존하지 않는다.
- 원격 값이 없거나 `true`/`false`로 읽히지 않으면 키별로 앱 기본값을 쓴다.

## 언제 받고 언제 적용하나

1. 앱 시작(`ChalkakApplication.onCreate`): 마지막으로 적용했던 값을 바로 쓴다. 기기에 저장되어 있으므로 오프라인이어도 그대로 쓴다. 한 번도 받은 적 없으면(첫 실행) 앱 기본값을 쓴다.
2. 같은 시점에 백그라운드에서 새 값을 받아(fetch) 바로 적용(activate)한다. 스플래시는 이 요청을 기다리지 않는다.
3. 실행 중에는 실시간 업데이트(`addOnConfigUpdateListener`)로 콘솔 변경을 받자마자 적용한다.
4. 화면은 진입할 때(AI 리뷰는 화면 `onResume`, 사진 편집은 사진 선택·탭 시점) 값을 확인한다. 이미 보고 있는 화면을 강제로 닫지는 않는다.

두 키 모두 장애 대응용 킬스위치라 "받자마자 적용"을 골랐다. 사용자가 보고 있는 화면이 갑자기 바뀌지 않도록 반영은 화면 진입 시점에 한다.

## 반영까지 걸리는 시간

| 상황 | 반영 시간 |
|---|---|
| 앱을 쓰는 중 (실시간 연결 정상) | 수 초 안에 적용, 다음 화면 진입부터 반영 |
| 실시간 연결이 없는 경우 | 다음 앱 실행. 단, 마지막 fetch 뒤 1시간이 지나야 새로 받는다 |
| 오프라인 | 온라인으로 돌아온 뒤 위 규칙대로 |

- 운영 앱(release)의 최소 fetch 간격은 1시간이다. Firebase 기본값인 12시간은 장애 대응에 너무 느리고, 너무 짧게 잡으면 요청 제한(throttling)에 걸린다. 실시간 업데이트가 반영 속도를 맡으므로 주기적 fetch는 보조 수단이다.
- debug 앱은 간격 0초로, 개발자 도구에서 언제든 다시 받을 수 있다.

## 운영 규칙

- debug(`com.stonefive.chalkak.debug`)와 release(`com.stonefive.chalkak`) 앱은 같은 Firebase 프로젝트를 쓴다. 조건 없이 값을 바꾸면 운영 앱에도 적용된다.
  - 테스트는 콘솔에서 "앱 = com.stonefive.chalkak.debug" 조건 값으로만 한다.
- 원격 설정에는 비밀 키·토큰을 두지 않는다. 응답이 기기에 평문으로 내려와 누구나 읽을 수 있다.
- 클라이언트 플래그는 UI를 숨길 뿐이다. 서버에서 막아야 하는 기능은 서버에서도 막는다.

## 개발자 도구 (debug 빌드)

설정 > 개발 > 개발자 도구 > 원격 설정에서 다음을 확인하거나 실행할 수 있다.

- 키별 현재 값과 출처(앱 기본값 / 원격)
- 마지막으로 받아 온 시각과 결과
- 지금 다시 받기
