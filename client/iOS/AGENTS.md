# Chalkak iOS — 프로젝트 메모리

> MUST: 특별한 이유가 없다면 반드시 지키는 규칙.
> DEFAULT: 기본 선택이며, 더 적합한 이유가 있으면 벗어날 수 있다.
>
> 검증되지 않은 구조를 미리 고정하지 않는다.

## MUST — Design System

- `DesignSystem`은 특정 feature에 의존하지 않는다.
- 여러 피처에서 같은 역할로 사용하는 UI는 중복 구현하지 않고
  `DesignSystem/Components`의 공통 컴포넌트를 재사용한다.
- Android와 디자인 의도, 상태, 컴포넌트 책임은 맞추되
  구현은 SwiftUI 네이티브 API와 iOS 관례를 따른다.
- 양쪽 플랫폼에 공통으로 존재하는 디자인 토큰과 컴포넌트는 의미 이름을 동일하게 유지한다.
  플랫폼 API 차이가 있을 때만 파라미터와 내부 구현 이름을 다르게 둔다.
- 공통 컴포넌트는 비즈니스 상태와 내비게이션을 소유하지 않는다.
  필요한 데이터와 이벤트를 외부에서 전달받는다.

## DEFAULT — 피처 구조

- 피처는 기본적으로 다음 구조를 따른다.

  ```text
  Features/Xxx/
  ├── XxxScreen.swift
  ├── XxxViewModel.swift
  ├── XxxViewState.swift
  └── Components/
  ```

- `ViewModel`과 `ViewState`는 화면 상태나 비동기 동작이 있을 때만 만든다.
- 내비게이션 연결용 `XxxRoute`는 실제로 화면 조립 책임이 필요할 때만 추가한다.
- 피처 전용 UI는 해당 피처의 `Components/`에 둔다.
- 여러 피처에서 재사용되는 UI만 `DesignSystem/Components/`에 둔다.

## MUST — 레이아웃 책임

- 화면 Safe Area, 화면 바깥 여백, 전체 폭은 호출하는 화면이 관리한다.
- 재사용 컴포넌트는 내부 배치, 내부 패딩, 고유 비율과 최소 터치 영역을 담당한다.
- 공통 컴포넌트가 특별한 이유 없이 다음 modifier를 적용하지 않는다.
  - 화면 기준 `.padding(.horizontal)`
  - `.safeAreaPadding(...)`
  - `.frame(maxWidth: .infinity)`
- 화면에 따라 달라지는 폭과 높이는 호출부가 `.frame(...)`으로 결정한다.
- 컴포넌트 자체에 고정 크기가 필요한 경우 그 이유를 이름이 드러나는 상수로 표현한다.

## MUST — 디자인 시스템 토큰

- 브랜드 색상과 본문 서체를 화면이나 컴포넌트에서 직접 선언하지 않는다.
- 색상과 타이포그래피는 `DesignSystem/Foundation`의 시맨틱 토큰을 사용한다.
- 반복해서 사용하는 간격과 모서리는 디자인 시스템 토큰을 사용한다.
- Figma에서 정한 컴포넌트 고유 크기, 테두리 두께, 아이콘 크기는
  의미가 드러나는 `private` 상수로 선언할 수 있다.
- SF Symbols의 크기와 굵기를 설정하기 위한 시스템 `Font` 사용은 허용한다.
- Android의 `dp` 값을 타입이나 코드로 공유하지 않고 iOS point(`CGFloat`)로 표현한다.

## MUST — 상태와 이벤트

- 화면의 비즈니스 상태와 비동기 작업은 공통 컴포넌트가 소유하지 않는다.
- 컴포넌트 본문에서 네트워크 요청이나 영속화 같은 부수 효과를 직접 실행하지 않는다.

## MUST — 접근성

- 상호작용 요소는 최소 44pt 터치 영역을 확보한다.
- 선택 가능한 컴포넌트는 선택 여부를 접근성 상태로 노출한다.
- 장식용 이미지와 중복 아이콘은 접근성 트리에서 숨긴다.

## DEFAULT — Preview

- 재사용 디자인 시스템 컴포넌트는 대표 상태를 확인할 `#Preview`를 둔다.
- 상태가 있는 컴포넌트는 가능한 범위에서 상태를 확인한다.
- Preview 전용 데이터가 제품 코드의 도메인 모델을 오염시키지 않도록 한다.
