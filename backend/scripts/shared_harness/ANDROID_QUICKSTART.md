# Android — 백엔드 정책 자동으로 받기

백엔드가 올린 공통 지침·스킬·정책을 자동으로 받아 Codex·Claude에서 사용한다. **최초 설치 후에는 정책 변경마다 pull·sync·apply를 직접 실행하지 않는다.**

> 이 자동 설치 개선은 아직 배포 전이다. 담당자가 배포와 앱별 연결 확인을 안내한 뒤 사용한다.

## 처음 한 번

1. Python 3.10 이상과 프로젝트를 읽을 수 있는 GitHub SSH 인증을 준비한다.
2. 담당자가 전달한 검토된 `install.sh`를 다운로드 폴더에 저장한다.
3. Android 프로젝트의 터미널을 열고 진행 중인 AI 작업을 정리한 뒤 실행한다.

```bash
bash "$HOME/Downloads/install.sh"
```

설치기가 필요한 도구 다운로드, 프로젝트 연결, 5분 주기 내려받기, Codex·Claude 세션 연결을 처리한다. Codex에서는 처음 표시되는 hook 검토·신뢰 절차를 완료한다. 앱이나 프로필 설정에 따라 hook이 차단되면 담당자에게 알린다. 신뢰 승인을 우회하지 않는다.

이후 새 세션에서 공통 정책의 **고정 버전 경로**가 전달되고 AI가 관련 문서를 실제로 읽는지 확인한다. 설치 성공만으로 앱 연결까지 확인한 것으로 판단하지 않는다. 설치로 추가된 로컬 파일·지침은 앱 기능 PR에 포함하지 않는다.

## 평소에는

- 평소처럼 Orca 또는 Codex 데스크톱에서 새 세션을 시작한다.
- 시작할 때 최신 배포를 확인하고 그 세션의 정책 버전을 고정한다.
- 기존 세션을 이어가면 기존 버전을 유지한다. 백엔드가 정책 변경을 알리면 필요한 작업을 정리하고 **새 세션**으로 시작한다.
- 앱 개발 브랜치와 코드는 자동 pull·merge하지 않는다.

## 오류나 정책 변경 요청

최신 확인 실패·hook 미실행·설치 충돌 메시지가 나오면 백엔드 담당자에게 전달한다. 실패 시 이전 정상 버전이 남아 있어도 최신 정책을 받은 것으로 판단하지 않는다.

공통 문서는 직접 수정하지 않는다. 정책이 맞지 않으면 **현재 규칙·문제 상황·원하는 변경·앱 영향**을 백엔드에 전달한다. 서버 반영 여부도 함께 확인한다.

다른 clone·프로필을 쓰거나 설치 도구 자체가 바뀌면 재설정이 필요할 수 있다. 자세한 상태 확인과 제거는 [전체 사용법](README.md#자동-모드-상태제거)을 따른다.
