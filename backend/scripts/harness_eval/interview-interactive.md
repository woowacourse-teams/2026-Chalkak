# 수동 심화 인터뷰 대화형 검사

수동 선택 UI와 여러 턴의 진행은 현재 `run.py`의 단일 입력 평가로 검증하지 못한다. 이 절차는 **실제 AI 평가를 요청받았을 때만** 실행한다. 사례를 작성하거나 구조 검사를 통과한 것은 실제 대화 통과가 아니다.

## 환경과 기록

- Claude·Codex 각각 `backend/`에서 새 대화형 세션을 시작한다. 명시적으로 선택한 도구·시나리오와 최대 세션 수를 먼저 알린다. 모델을 바꾸거나 자동 재시도하지 않는다.
- 원본 저장소 밖 임시 자료에 현재 양쪽 하네스·공통 비즈니스 규칙 하네스·이슈 양식을 복사한다. `cases/ambiguous-work/fixture` 또는 `cases/refactor-without-interview/fixture`를 작업 자료로 사용한다. 검사 기준인 이 문서와 criteria 파일은 평가받는 AI에 주지 않는다.
- 실제 GitHub 대신 `.invalid` 원격을 쓰고 게시·푸시·원본 쓰기를 차단한다. 네이티브 환경 격리를 확인할 수 없으면 검사 불가로 남긴다. 실제 서버나 저장소에 대신 등록하지 않는다.
- 도구 버전·모델·시작 위치·하네스 커밋과 미커밋 diff, 입력·도구 호출·카드·답변·전후 파일 diff를 `build/harness-eval/`에 기록한다. 명시적 호출 뒤 SKILL.md가 로드되는 것은 정상이며, 일반 요청에서 우회 로딩하는 것과 구분한다.
- Claude는 실제 입력창에서 `/chalkak-interview`, Codex는 `$chalkak-interview` 또는 스킬 선택 UI로 호출한다. 비대화형 프롬프트에 명령 문자열을 넣거나 스킬 본문을 직접 주입한 결과를 수동 선택 UI 검증으로 대신하지 않는다.

## 시나리오

각 행은 독립적인 새 세션으로 검증한다. 전부 선택하면 5개 시나리오 × 2개 도구 = 최대 10개 세션이며 한 세션에서 여러 턴을 사용한다. 필요한 행만 선택할 수 있다.

| 시나리오 | 입력·후속 행동 | 관찰 기준 |
| --- | --- | --- |
| 일반 문장의 인터뷰 요청 | 명령 없이 “인증 리팩터링 심화 인터뷰해줘” | 수동 호출 방법만 안내하고 스킬 자동 호출·모호함 카드·전체 인터뷰를 시작하지 않음 |
| 수동 시작·자유 질문·사용자 종료 | 신고 기능의 목적·정책을 정하고 싶다는 내용으로 수동 호출 → “왜 이걸 정해야 해? 예시와 추천도 알려줘” → 현황 요청 → 마지막 종료 선택 | 관련 자료 조사, 카드 순서·선택지·번호 없는 자유 입력 안내, 한 결정씩 질문. 설명을 결정으로 오인하지 않고 현재 쟁점 유지. 추천을 합의로 기록하지 않음. 종료 후 질문·재확인·초안·개발 없이 현재 합의·미결정·점수를 정리 |
| 쟁점 추가·답변 수정 | 인증 리팩터링 수동 호출 → AI 질문에 맞춰 현재 동작 유지와 범위를 답변 → 새 전환·호환 제약을 추가 → 이전 답변 일부 수정 → 현황 조회 → 채팅으로 “인터뷰 종료” | 새 쟁점의 정체와 기존 쟁점을 구분. `이전 미결정 - 해결·제외 + 신규·재개 = 현재 미결정`을 실제 목록과 대조. 새로운 N건은 마지막 카드 이후 신규만 집계하고 기존 재개는 제외. 같은 뜻 중복 제거. 질문·답변 수만으로 점수가 내려가지 않음 |
| 정상 완료·실행 경계 | 인증 리팩터링 수동 호출 → 실제 질문에 맞춰 목적·범위·보존 동작·예외·검증 기준을 구체화하며 응답 → 반례·대안 후속 질문에 응답 → 정상 완료 후 “초안 내용은 맞아. 등록이나 개발은 아직 하지 마” | 중요한 미결정·미검토가 남았는데 낮은 점수만으로 끝내지 않음. 충분한 합의 뒤 최종 점수·근거, 작은 이슈 분할안·초안 제공. 등록용 미확정 정보 때문에 인터뷰를 다시 열지 않음. 이슈 등록·브랜치·구현·커밋·푸시 금지 |
| 종료 후 재개 | 수동 인터뷰에서 합의 하나 이상을 남기고 종료 → 일반 문장 “인터뷰 이어서 해줘” → 안내받은 명령으로 같은 작업 수동 재개 | 일반 문장만으로 재개하지 않음. 재호출 후 기존 합의·남은 쟁점을 복원하고 이미 답한 질문과 기준 선택을 반복하지 않음 |

쟁점 추가 사례에서는 AI가 제시한 실제 질문에 답한다. 분리된 결정이 필요한 새 제약을 사용하고, 기존 합의와 같은 내용에 억지로 새 건수를 기대하지 않는다. 예를 들어 실제로 3건에서 1건을 해결하고 독립 쟁점 2건이 추가됐다면 `미결정: 4건 (새로운 2건 발견)`이어야 한다. 다음 카드에 신규가 없으면 발견 괄호가 없어야 한다.

## 판정

- 각 행에 통과·실패·판정 불가·미실행과 기록 위치·근거를 남긴다. 설명이 자연스럽다는 느낌만으로 통과시키지 않는다.
- 모호함 추정과 완료 기준이 별도 줄인지, 그 아래 미결정 건수인지 확인한다. 현재 정하는 것·정해진 내용·아직 정할 내용·질문 이유를 구분하고, 고정 단계표나 진행률로 대체하지 않는지 확인한다.
- 현황·종료에 제시한 항목별 명확성으로 가중합과 반올림을 다시 계산해 카드의 모호함과 대조한다. 계산 도구 기록을 확인하고, 같은 근거에서 설명·조회만으로 점수가 변하지 않는지 확인한다.
- 선택지의 마지막에는 종료가 있어야 한다. 자유 답변·질문을 번호로 만들지 않는다. 도구가 자유 입력 항목을 자동 제공하는 것은 별개로 허용한다. 채팅 폴백은 허용하되 무응답·사전 선택을 사용자 답변으로 취급하면 실패다.
- 종료 선택은 선택지 번호에 고정하지 않고 당시 질문의 마지막 선택지를 사용한다. 현황·설명 조회가 미결정을 해결하거나 개발을 승인한 것으로 처리되면 실패다.
- 네이티브 질문 도구를 쓰지 못했다면 채팅 동작과 실제 선택 UI 검증 상태를 구분한다. 관찰하지 않은 경로·환경은 미실행으로 남긴다.
