# 피드백 작업 확인 자료

인터뷰 결과와 초기 분할은 승인됐으며, 메인 #900 아래 #901에 피드백 작업을 모았다. 처음에는 12개 파일 / 약 500줄로 추정했다. 구현 전 관련 계약·테스트 경계를 확인한 결과 아래 예상으로 바뀌었다. 수치는 테스트 포함 추가+삭제이며 문서 제외다. 아직 구현·검증은 하지 않았다.

| 동작 | 정상·실패 계약 | 예상 파일 수 | 운영 코드 | 테스트 | 선행 계약 |
| --- | --- | --- | --- | --- | --- |
| 접수 | 로그인, 내용 1~1000자, DB 성공 후 응답, 저장 실패는 성공으로 처리하지 않음 | 6 | 140 | 100 | 없음 |
| Slack 알림 | 접수 성공 후 알림, Slack 실패가 성공한 접수를 취소하지 않음 | 8 | 230 | 190 | 접수 저장 |
| 관리자 조회 | 관리자만 페이지 목록·상세 조회, 없는 상세와 DB 조회 실패 처리 | 10 | 240 | 170 | 접수 저장 |
| 키워드 검색 | 관리자 목록을 내용 키워드로 필터링, 페이지 결과·건수 일치, 무결과 정상, 조회 실패 분리 | 7 | 220 | 160 | 기본 목록 조회 |

예상 변경 경로는 동작 사이 중복이 없어 총 31개 파일 / 1,450줄이다. 접수 API와 관리자 목록·상세 API는 아직 없다. 저장 모델은 기존 인증 계층과 연결한다. Slack은 저장 뒤의 확장이고 검색은 기본 목록에 필터를 추가하는 확장이다. API URI·검색 세부 일치 규칙은 구현 전에 기존 정책과 대조해야 한다. 삭제·수정·첨부파일은 합의에서 제외했다.
