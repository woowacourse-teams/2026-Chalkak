#924의 첫 커밋 단위를 시작해줘. 합의한 범위는 아래와 같아. 구현·검증까지 진행하고 결과를 보여줘. 커밋은 내가 변경을 보고 승인할 때 생성해줘.

피드백 조회 날짜 검증이 UTC 기준이라 한국 시간으로 오늘인 날짜를 미래라고 거부하는 오류가 있어. 조회 날짜는 그대로 유지하며 미래 여부는 한국 날짜로 판단해야 해. 과거·오늘은 허용하고 내일은 기존 BusinessException/BUSINESS_ERROR로 거부해. 예외 응답이나 클라이언트 분기에는 변화가 없어.

같은 도메인에 FeedbackDateValidator를 두어 이 검증을 담당하게 하고 FeedbackQuery는 이를 호출하도록 해줘. 기존 Clock 주입을 활용하고 실제 시스템 시각에 의존하는 테스트는 피하자. 기존 unrelated/LegacyLabel은 그대로 두고 API·DTO·DB는 추가하지 않아. 두 번째 단위인 관리자 검색과 README 수정은 아직 시작하지 마.

작은 작업 자료의 README에 있는 오프라인 Java 검사 명령을 사용하면 돼. 원본 서비스 개발이 아닌 분리된 개발 자료야.
