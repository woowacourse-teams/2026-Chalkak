# 백엔드 AI 자동 리뷰

백엔드 PR을 처음 발견하면 선택한 AI가 사전 리뷰를 작성한다. **리뷰 계정별 PR당 최초 1회**이며 추가 푸시에는 재리뷰하지 않는다. 이후 수정 확인·최종 리뷰·승인·병합은 사람이 담당한다.

## 대상

- base가 `be/develop`이고 `Server` 라벨이 있는 열린 PR
- Draft가 아니며 현재 GitHub 계정이 작성하지 않은 PR
- 같은 리뷰 계정이 아직 자동 리뷰하지 않은 PR. 이전 head SHA·다른 AI로 남긴 완료 기록도 포함한다.

다른 팀원 계정은 같은 PR을 각자 한 번 검토할 수 있다. 같은 계정의 감시 프로그램은 한 컴퓨터에서만 운영한다. 로컬 실행 잠금은 여러 컴퓨터 간 동시 호출까지 막지 않는다.

## 댓글과 사용량 기준

| 검토 유형 | PR 라벨 | 파일 한도 | 추가+삭제 줄 한도 |
| --- | --- | --- | --- |
| 일반 변경 | `refactor` 없음, 유형 미지정, 또는 `refactor`와 `feat`·`fix`·`chore` 혼합 | 30개 | 1,200줄 |
| 리팩터링 | `refactor` 있음 + `feat`·`fix`·`chore` 없음 | 40개 | 1,800줄 |

모든 대상에는 `Server`가 필요하다. 리팩터링에 동반된 `docs`·`test`·`style`은 확대 한도를 유지한다. 일반 변경은 요구사항·예외 처리·권한·입력·기존 기능 연결을, 리팩터링은 기존 동작·API 계약·호출부·트랜잭션·성능·회귀 테스트를 중점 검토한다. 혼합 변경은 두 관점을 함께 적용한다.

PR 작성 시 실제 diff와 합의한 범위를 보고 유형 라벨을 붙인다. 감시 프로그램은 제목이나 브랜치 이름으로 추측하지 않는다. 라벨은 동작 보존의 증명이 아니므로 잘못 붙인 라벨까지 사전에 판별할 수는 없다. AI가 실제 기능·정책 변경을 발견하면 함께 검토하되 추가 호출하지 않는다.

- 실제 오류·요구사항 위반·보안·데이터 정합성·API 계약 문제·중요한 회귀 테스트 누락만 최대 5개 남긴다. 취향·추측은 제외한다. 숫자로 된 확신도 임계값이나 최소 변경량 기준은 없다.
- 문제마다 원인이 되는 변경 줄에 개별 댓글을 단다. 적절한 줄이 정말 없는 공통 문제만 이유와 함께 리뷰 본문에 작성한다. 본문에 코드 댓글을 다시 모아 쓰지 않는다.
- 문제가 없어도 `발견된 문제 없음`과 확인하지 못한 범위를 짧게 게시하고 최초 검토를 완료 처리한다.
- **위 유형별 파일·줄 한도 또는 공통 diff 200,000자 중 하나라도 초과**하면 AI 호출 없이 유형·적용 한도를 포함한 수동 검토 안내만 남긴다. 한도와 같은 값은 허용한다. 이는 사용량을 제한하는 운영 설정값이며, 검증된 정확도 기준이나 토큰 예산 보장은 아니다.
- AI 생성 실패·잘못된 JSON·유효하지 않은 댓글 위치·생성 중 프로세스 종료는 기록하고 재호출하지 않는다. 실패를 `발견된 문제 없음`으로 게시하지 않는다.
- 게시만 실패하면 저장된 결과로 최대 3회(첫 시도 포함) 게시를 시도한다. 매번 원격 리뷰를 확인해 이미 성공한 게시를 반복하지 않는다. AI는 다시 호출하지 않는다.
- 검토 중 새 커밋이 올라오거나 PR이 닫힘·Draft 전환·대상 제외·검토 유형 변경되면 이전 결과 게시와 자동 재검토를 중단하고 로컬 상태·로그에 남긴다. 게시 직전 조회 이후의 푸시는 막을 수 없으므로 리뷰는 검토한 커밋에 고정한다. 완료·보류 이후 유형 라벨 변경도 횟수를 초기화하지 않는다.
- 추가 리뷰 명령·PR 댓글 트리거는 제공하지 않는다. AI 변경·감시 재시작·PR 재개방도 횟수를 초기화하지 않는다.

## 최초 설치

macOS에서 저장소를 받은 뒤 백엔드 디렉터리에서 실행한다.

```bash
git pull
cd backend
./scripts/pr-review/manage.sh install
```

화면에서 `1. Codex` 또는 `2. Claude`를 선택한다. `gh`와 선택한 AI CLI가 설치되고 로그인되어 있어야 한다. 선택값과 처리 기록은 `~/Library/Application Support/Chalkak PR Review/`에만 저장된다.

설치 후 macOS 로그인 시 자동으로 시작하고 `launchd`가 5분마다 검사 프로그램을 한 번 실행한다. 검사 사이에는 프로그램이 계속 떠 있지 않는다. 변경된 PR이 없으면 AI를 호출하지 않는다. 컴퓨터가 잠들거나 꺼진 동안 등록된 PR은 다음 실행에서 확인한다.

이전 버전에서 업데이트했다면 `install`을 다시 실행한다. 기존 설정(version 1)으로 새 프로그램의 AI 호출·게시를 시작하지 않으며 설정 갱신을 안내한다. 기존 리뷰는 GitHub의 작성 계정과 완료 표시로 판별한다. 계정 정보가 없는 이전 실패·미게시 기록은 안전하게 보류하고, 예전 본문 전체 결과를 다시 게시하지 않는다. 팀원도 각자 프로그램을 업데이트해야 새 정책이 적용된다.

사용량이 한꺼번에 소모되지 않도록 한 번 확인할 때 새 PR 하나만 리뷰한다. 여러 PR이 대기 중이면 오래된 PR부터 5분 간격으로 처리한다.

## 관리

```bash
# 실행 상태와 선택한 AI 확인
./scripts/pr-review/manage.sh status

# 일시 중지와 재시작
./scripts/pr-review/manage.sh stop
./scripts/pr-review/manage.sh start

# AI 변경
./scripts/pr-review/manage.sh configure

# 아직 검토하지 않은 PR을 즉시 한 번 확인 (재리뷰 아님)
./scripts/pr-review/manage.sh run-once

# 최근 로그 확인
./scripts/pr-review/manage.sh logs

# 자동 실행과 로컬 설정 완전 제거
./scripts/pr-review/manage.sh uninstall
```

`status`에는 마지막 GitHub 확인 시각·성공 여부·발견한 PR 수와 누적 처리 결과가 표시된다. 리뷰가 실제로 게시되면 GitHub PR과 `logs`에도 기록이 남는다.

감시 자체는 GitHub CLI만 사용하므로 AI 토큰을 소비하지 않는다. 조건에 맞는 미검토 PR에서 실제 리뷰를 생성할 때만 선택한 계정의 사용량을 쓴다. 실패·중단된 시도 기록은 횟수 보호를 위해 자동 삭제하지 않는다. 로컬 기록 삭제·재설치는 게시되지 않은 과거 호출까지 복원할 수 없으므로 사용량 초기화 수단으로 사용하지 않는다.

## 검증

```bash
python3 -B -m unittest discover -s scripts/pr-review -p '*_test.py'
python3 scripts/check_harness.py
```

모의 GitHub·AI로 위치 검증, 호출 횟수, 실패·재시도·상태 이관을 검사한다. 실제 계정의 리뷰를 게시하거나 AI를 호출하는 검사는 아니다.

## 권한 범위

- AI는 읽기 전용 임시 세션에서 동작하며 PR 코드를 실행하거나 수정하지 않는다.
- GitHub 리뷰는 `COMMENT`로만 등록한다.
- 자동 승인, 변경 요청, 병합과 브랜치 삭제는 하지 않는다.
