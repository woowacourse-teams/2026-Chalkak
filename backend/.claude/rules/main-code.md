# 운영 코드 컨벤션

## 적용 범위

- 새로 작성하거나 수정한 코드에만 적용한다.
- 관련 없는 기존 코드는 컨벤션 적용을 이유로 변경하지 않는다.
- 완료 전 변경한 코드를 아래 규칙으로 다시 확인한다.

## 기본 스타일

- Google Java Style을 기본으로 한다.
- 이 문서의 팀 규칙과 충돌하면 팀 규칙을 우선한다.
- 블록 들여쓰기는 공백 4칸을 사용한다.
- 줄바꿈 후 계속되는 줄은 기존 줄보다 최소 8칸 들여쓴다.

## 괄호와 블록

- `if`, `for`, `while`은 한 줄이어도 중괄호를 사용한다.
- 여는 중괄호는 선언문과 같은 줄에 둔다.
- 빈 블록을 작성하지 않는다.
- 매개변수가 3개 이상이면 매개변수마다 줄을 나눈다.

## 메서드 네이밍

- 메서드명은 동사로 시작한다.
- 동일한 의미에는 동일한 동사를 사용한다.
- `getXxx`: 반드시 존재하며 없으면 예외
- `findXxx`: 없을 수 있으며 `Optional` 또는 nullable 반환
- `createXxx`: 신규 객체 또는 리소스 생성
- `buildXxx`: Builder 또는 객체 조립
- `generateXxx`: 랜덤값, 토큰 또는 코드 생성
- `updateXxx`: 일반적인 상태 수정
- 도메인 상태 전환은 구체적인 동사 사용 가능
- 단순 수정 의미의 `changeXxx`, `modifyXxx`는 사용하지 않음
- `deleteXxx`: 삭제
- `removeXxx`: 컬렉션 요소 제거
- `validateXxx`: 입력값, 상태 또는 비즈니스 규칙 검증
- `verifyXxx`: 인증 또는 진위 확인
- `toXxx()`: 인스턴스를 다른 타입으로 변환
- `fromXxx()`: 다른 타입으로부터 생성하는 정적 메서드
- Converter의 `convert()`: 양쪽 타입에 변환 책임을 두지 않는 변환

Boolean 반환 메서드는 긍정형으로 작성한다.

- 상태 여부: `isXxx`
- 보유 또는 포함 여부: `hasXxx`
- 행위 가능 여부: `canXxx`
- 저장소 존재 여부: `existsXxx`

## 클래스 내부 배치 순서

1. 상수
2. 필드
3. 생성자
4. `public` 메서드
5. `protected` 메서드
6. `private` 메서드
7. getter와 setter
8. `hashCode()`
9. `equals()`
