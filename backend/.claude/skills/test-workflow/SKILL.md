# 테스트 작업 흐름

## 적용 범위

다음 작업에 적용한다.

- 새로운 기능 또는 비즈니스 규칙 구현
- 기존 동작 변경
- 버그 수정

테스트 유형·배치·네이밍·DB 격리와 계층별 필수 검증 항목은 `test-code` 컨벤션을 따른다.

운영 코드 작성 규칙은 `main-code` 컨벤션을 따른다.

## 1. 케이스 목록 작성

1. 구현 전에 테스트 코드 없이 검증할 케이스 목록만 작성한다.
2. 요구사항, 이슈 완료 기준, 관련 비즈니스 규칙 문서에서 케이스를 도출한다. 구현한 코드에서 케이스를 도출하지 않는다.
3. `test-code`의 계층별 필수 검증 항목을 체크리스트로 사용해 변경이 닿는 계층마다 케이스를 채운다.
4. 기존 동작이 유지돼야 하는 회귀 케이스를 포함한다.

## 2. 구현

- 목록에 없는 동작이 필요해지면 구현 전에 목록에 먼저 추가한다.

## 3. 테스트 작성과 대조

1. 목록의 케이스마다 테스트를 작성한다.
2. 구현 중 발견한 분기가 목록에 없으면 목록과 테스트에 함께 추가한다.
3. 작성 후 목록과 실제 테스트를 1:1로 대조해 누락을 확인한다.
4. `test-code`에서 테스트 제외 대상으로 정한 코드에는 테스트를 추가하지 않는다.

## 버그 수정

- 운영 코드를 고치기 전에 버그를 재현하는 테스트를 먼저 작성한다.
- 재현 테스트가 기대한 이유로 실패하는지 확인한다.
- 환경 설정, 외부 시스템 또는 무관한 기존 오류로 인한 실패는 재현으로 인정하지 않는다.
- 동일한 버그가 다시 발생하지 않도록 재현 테스트를 유지한다.

## 기존 테스트 보호

- 운영 코드를 잘못된 상태로 유지하기 위해 테스트를 삭제하거나 검증을 약화하지 않는다.
- 요구사항이 변경된 경우에만 기존 테스트의 기대 결과를 변경한다.
- 테스트를 변경했다면 어떤 요구사항이 달라졌는지 확인한다.
- 관련 없는 기존 테스트와 운영 코드는 함께 수정하지 않는다.

## 완료 전 확인

- 케이스 목록과 테스트가 1:1로 대응하는지 확인한다.
- 버그 수정이면 재현 테스트가 수정 전에 실패했는지 확인한다.
- 변경한 동작과 관련된 테스트를 실행한다.
- 필요한 범위의 전체 테스트를 실행하여 회귀가 없는지 확인한다.
- 완료 결과에 케이스 목록, 실행한 테스트와 결과를 기록한다. 실행하지 못한 테스트는 통과로 보고하지 않는다.
