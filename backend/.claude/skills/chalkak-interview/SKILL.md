# 찰캌 심화 인터뷰

## 수동 시작과 범위

- 사용자가 `/chalkak-interview 작업 내용`으로 직접 호출하거나 스킬 선택 UI에서 선택했을 때만 시작한다. 일반적인 인터뷰 요청 문장만 있으면 수동 실행 방법을 안내하고 자동 호출하거나 절차를 대신 수행하지 않는다.
- 신규 기능, 기존 기능 변경, 리팩터링 모두 다룬다. 작업 종류·불명확한 요구사항·새 세션을 이유로 자동 시작하지 않는다.
- 한 번 시작한 같은 인터뷰는 사용자 답변으로 이어간다. 매 질문마다 재호출하지 않는다. 종료 후 새 인터뷰·재개는 다시 수동 호출하며 기존 합의를 재사용한다.
- 추가 인터뷰는 기존 합의를 유지하고 미검토 쟁점을 다룬다. 처음부터 재검토를 요청하면 기존 전제도 검토하되 이슈·브랜치·코드를 삭제하거나 초기화하지 않는다.
- 인터뷰 중에는 관련 자료를 조사하고 합의를 정리한다. 수동 호출 자체는 파일 수정, 이슈 등록, 브랜치 생성, 개발·커밋·푸시·PR 등록 승인이 아니다.

## 조사와 심화 질문

1. 관련 코드·테스트·문서를 먼저 읽고 현재 동작, 사용자 결정, AI 제안과 미확인 사실을 구분한다. 코드에서 확인 가능한 사실은 사용자에게 대신 조사하게 하지 않는다.
2. 목적, 포함·제외 범위, 유지 조건과 완료 기준에서 결정이 필요한 쟁점을 찾는다. 여러 기능·흐름이면 각각 추적한다.
3. 구현이나 검증에 가장 큰 영향을 주는 쟁점을 골라 한 번에 한 결정을 묻고 답변을 기다린다. 선택지는 의미가 겹치지 않게 제시하고, 질문 이유에는 선택에 따라 무엇이 달라지는지 적는다.
4. 답변의 중요한 전제를 구체적인 사례·반례로 확인하고, 더 작은 변경이나 대안의 장단점을 검토한다. 관련된 실패·예외·권한·호환성 경계를 확인하는 후속 질문을 수행한다. 질문 개수나 고정 단계를 채우기 위해 해결된 쟁점을 반복하지 않는다.
5. 추상적인 합의를 테스트나 관찰 가능한 완료 기준으로 바꾼다. 중요한 결정을 AI 추천만으로 확정하지 않는다.

관련된 관점만 적용한다.

| 대상 | 확인할 경계 |
| --- | --- |
| 신규·기존 기능 | 사용자·권한·상태, 성공·실패 동작, API 계약, 중복·동시 요청, 외부 부수 효과 |
| 리팩터링 | 해결하려는 문제, 바꿔도 되는 구조·범위, 보존할 동작·예외 응답·데이터, 호환 조건, 회귀 검증 |
| 성능·연동 변경 | 측정 근거와 목표, 부하·실패·재시도, 변경·전환 범위와 검증 방법 |

## 대화와 쟁점 관리

- 각 쟁점의 의미, 중요 여부, 미결정·해결·합의로 제외한 상태, 결정 근거와 관련 합의를 대화 맥락에 유지한다. 중요한 쟁점은 결정에 따라 목적·범위·권한·데이터·호환성·완료 기준 등이 달라지는 항목이다.
- **결정 답변:** 선택지나 자유 입력의 의미를 반영한다. 기존 합의와 충돌하면 그 영향만 확인하고 임의로 한쪽을 선택하지 않는다.
- **설명·예시·추천 요청:** 현재 쟁점에서 설명한다. 추천은 제안으로 표시하고 선택한 것으로 간주하지 않는다. 설명 요청 자체로 해결 처리하거나 모호함을 낮추지 않는다. 새 사실이 확인됐다면 그 근거에 한해 다시 평가한다.
- **답변 수정:** 영향을 받는 합의·쟁점을 다시 열고 모호함을 재평가한다. 무관한 합의를 초기화하지 않는다.
- **현황 요청:** 전체 합의, 남은 쟁점과 영향, 충돌·미확인 사항, 종료에 필요한 확인 내용을 보여준다. 현황 조회는 결정 답변이 아니다.
- **종료 요청:** 아래 사용자 종료 절차를 즉시 따른다. 선택지가 아닌 채팅으로 종료해도 같다.
- 미결정은 질문 개수가 아니라 현재 결정이 필요한 고유 쟁점 수다. 표현만 바뀐 쟁점을 중복 계산하지 않으며 미검토 영역을 근거 없이 쟁점으로 세지 않는다.
- 새 쟁점이 생기면 현재 건수를 갱신하고 다음 카드에만 `(새로운 N건 발견)`을 표시한다. 하나 해결하고 둘이 추가되면 총건수는 하나 증가한다. 재개된 기존 쟁점은 새 발견으로 세지 않는다. 새 쟁점의 내용도 짧게 알린다.
- 아직 검토하지 않은 중요한 영역이 있으면 미결정 건수가 0이어도 완료로 판단하지 않는다. 필요하면 현황에 별도로 알린다.
- 별도의 상태 파일을 자동 생성하지 않는다. 대화 요약·인계에는 합의, 쟁점과 근거, 점수, 현재 질문, 마지막 카드 이후 새로 발견한 쟁점, 진행·종료 상태를 남긴다.

## 질문 카드와 선택 UI

결정을 물을 때 아래 형식을 사용한다. 수치와 내용은 예시이며 실제 근거로 채운다. 종료 기준은 기본 15%이며 사용자가 기준 변경을 명시한 경우에만 변경한다.

> **모호함 추정: 25%**
>
> **완료 기준: 15% 이하 + 중요 미결정 해소**
>
> **미결정: 4건 (새로운 2건 발견)**
>
> **현재 정하는 것: 리팩터링 범위**
>
> - **정해진 내용:** 로그인 동작과 API 응답은 그대로 유지
> - **아직 정할 내용:** DB 구조도 바꿔도 되는지
> - **이걸 묻는 이유:** DB 변경 허용 여부에 따라 작업 범위가 달라짐
>
> **질문: 이번 리팩터링에서 DB 구조 변경도 허용할까요?**
>
> ① 기존 DB 구조 유지
>
> ② 필요하면 변경 허용
>
> ③ 인터뷰 종료
>
> 💬 **직접 답변하거나 질문해도 됩니다.**
>
> 예: “일부 테이블만 변경하고 싶어”, “DB를 바꾸면 어떤 영향이 있어?”

- 모호함 아래에 완료 기준, 그 아래에 미결정을 표시한다. 새 쟁점이 없으면 발견 괄호를 생략한다. 정해진 내용이 없으면 아직 없다고 적는다.
- 선택지 수에 맞춰 번호를 붙이고 **인터뷰 종료를 마지막 선택지**로 둔다. 질문 도구가 번호를 붙이면 선택지 문구에 번호를 중복해서 넣지 않는다. 직접 답변·질문 안내에는 번호를 붙이지 않는다. 사용자는 도구의 자유 입력 또는 일반 채팅으로 답하거나 질문할 수 있다.
- 고정 단계표·전체 진행률은 표시하지 않는다. 현재 질문과 관련된 합의만 카드에 담고 전체 합의는 현황 요청과 종료 때 보여준다.
- 설명만 하는 응답에서는 카드를 반복하지 않는다. 설명 후 결정을 다시 물을 때 최신 카드와 선택지를 보여준다.
- 질문에는 `AskUserQuestion`을 사용하되 현재 도구의 선택지 수 제한을 따른다. 사용할 수 없거나 필요한 자유 입력·종료 선택을 표현할 수 없으면 채팅으로 묻는다.
- 질문 도구를 쓰면 카드와 자유 입력 안내를 함께 제공하고 선택지는 도구에 표시한다. 같은 질문·선택지를 채팅과 도구에 중복 출력하지 않는다. 도구 질문만 별도로 보여도 맥락을 이해할 수 있게 작성한다.
- 비동기 질문도 사용자가 답하기 전에는 다음 질문이나 의존하는 결정을 진행하지 않는다. 무응답·기본 선택지·도구 종료를 답변이나 종료 선택으로 간주하지 않는다.

## 모호함 평가

| 항목 | 가중치 | 판단 기준 |
| --- | --- | --- |
| 의도 | 25% | 해결할 문제와 필요한 이유 |
| 결과 | 20% | 기대하는 동작·구조·측정 결과 |
| 범위 | 20% | 포함·제외 범위와 AI가 결정할 수 있는 범위 |
| 제약 | 15% | 정책·권한·예외·보존 동작·호환 조건 |
| 완료 기준 | 10% | 성공·실패와 회귀를 검증할 사례 |
| 기존 시스템 이해 | 10% | 코드·계약·문서에 근거한 변경 영향 |

- 명확성은 항목별 0~1로 평가한다. 0은 정보 없음, 0.5는 방향만 확인, 0.75는 구체적이나 중요한 경계 미정, 1은 근거와 검증 가능한 합의가 충분함이다.
- 모호함(%) = `100 × (1 − 명확성 점수의 가중합)`. 근거를 유지하고 카드에는 정수로 반올림해 표시한다. 종료 판정은 반올림 전 값으로 한다.
- 항목별 명확성·근거와 계산한 모호함을 한 묶음으로 유지한다. 점수를 새로 정하거나 변경할 때는 사용 가능한 계산 도구 또는 읽기 전용 계산 명령으로 가중합·반올림을 검산한다. 현황·종료 요약도 같은 항목별 값과 계산 결과를 사용하며, 근거가 바뀌지 않으면 점수만 임의로 바꾸지 않는다. 산술 오류를 발견하면 추정 근거의 변경과 구분해 정정한다.
- 점수는 AI의 추정이며 누락률·진행률·완벽함을 뜻하지 않는다. 최초 카드에서 이를 짧게 안내한다. 새로운 제약·모순으로 점수가 오를 수 있으며, 증가하거나 큰 폭으로 바뀌면 이유를 짧게 설명한다.
- 답변 수나 질문 수만으로 점수를 낮추지 않는다. 종료 평가·현황 요청 때 항목별 근거와 남은 빈틈을 보여준다.
- 정상 완료는 **기준 이하 + 중요 미결정 해소 + 관련 영역 누락 확인 + 심화 후속 질문 수행 + 검증 가능한 완료 기준**을 모두 충족해야 한다. 낮은 평균으로 핵심 미결정이나 미검토 영역을 덮지 않는다.

## 완료·종료와 초안

- **정상 완료:** 목적, 포함·제외 범위, 보존할 동작, 결정 사항과 근거, 예외·실패 처리, 완료 기준, 남은 경미한 사항을 정리한다. 점수와 종료 근거를 보여준다.
- 서비스 정책 합의가 있으면 공통 [business-rules](../../../../.claude/skills/business-rules/SKILL.md)로 관련 규칙과 대조해 초안에 연결한다. 인터뷰 중 규칙 문서를 수정하거나 합의만으로 반영 완료라고 하지 않는다.
- 정상 완료 후 `Skill` 도구로 [work-breakdown](../work-breakdown/SKILL.md)을 **분할안·초안만 작성하는 범위**로 호출한다. 작은 작업은 하나로 유지하고 [issue-pr-workflow](../issue-pr-workflow/SKILL.md)의 양식으로 초안을 보여준다. 기존 이슈가 있으면 변경된 합의와 초안만 정리하며 새 이슈를 전제하지 않는다.
- 인터뷰 밖의 등록용 계정·라벨·브랜치 정보가 미확정이면 초안에 미확정으로 표시하고 등록 전에 확인한다. 이를 인터뷰 미결정 건수나 모호함에 섞지 않는다.
- **사용자 요청으로 종료:** 추가 질문이나 종료 재확인 없이 즉시 멈춘다. 현재 모호함·기준 충족 여부, 확정된 내용, 남은 쟁점과 영향을 정리한다. 정상 완료로 표시하거나 미정 사항을 확정하지 않는다. 요청하지 않은 이슈 초안 작성이나 개발로 이어가지 않는다.
- 인터뷰 중 “이제 시작해”처럼 구현 전환을 명시하면 질문을 멈추고 합의·미결정 사항을 인계한다. 인터뷰 답변을 등록·개발 승인으로 확대하지 않고 요청된 실행 범위는 별도로 확인한다.
- 정상 완료 후 초안 내용의 확인과 등록·개발 실행 승인을 구분한다. 명시적인 후속 실행 요청이 있을 때만 해당 워크플로로 연결한다. “초안만”, “이슈만 등록” 등 좁힌 범위를 유지한다.
