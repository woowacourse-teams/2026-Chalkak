# 이슈·PR 작업 분할

## 분할 기준

- 목적은 사람이 각 PR의 의도·정책·변경을 이해할 수 있게 하는 것이다. 작은 작업은 이슈·PR 하나로 유지하며, **작업 이슈 하나 = 브랜치 하나 = PR 하나**를 기본으로 한다.
- 서로 다른 목적·정책·도메인·외부 연동이나 독립적인 리팩터링이 섞이면 분리한다. 파일 수와 변경량은 신호로만 쓰고, 고정 상한이나 예상 리뷰 시간으로 결정하지 않는다.
- 각 단위는 선행 변경이 포함된 해당 브랜치에서 동작하고 검증할 수 있어야 한다. 구현과 관련 테스트를 함께 두며 Controller·Service·Repository 같은 계층만으로 기계적으로 나누지 않는다.
- 분리하면 같은 정책 설명을 반복하거나 함께 바뀌어야 하는 변경이 흩어질 때는 묶는다. 커밋만 작게 나눠 전체 PR 크기를 유지하는 것으로 대신하지 않는다.

## 의존 관계와 제안

- **B 구현에 A의 코드·계약이 필요한가**로 의존성을 판단하고 이유를 적는다. 같은 기능에 속하거나 파일을 함께 수정한다는 이유만으로 선후 관계를 만들지 않는다.
- 독립 작업은 각각 개발 통합 브랜치에서 시작한다. 의존 작업은 선행 작업 브랜치 위에서 개발하고 그 브랜치를 PR 대상으로 삼는 Stacked PR로 진행한다. 선행 PR 등록 후 병합을 기다리지 않고 후속 개발을 이어간다.
- B와 C가 각각 A에만 의존하면 그 관계를 그대로 표시한다. B → C 같은 가짜 의존 관계를 만들지 않으며, 여러 선행 작업이 필요한 경우 필요한 코드가 모이는 기준과 순서를 명시한다.
- 선행 작업의 핵심 정책·계약이 미정이면 영향을 받는 후속 작업부터 쌓지 않는다. 확정할 쟁점을 밝히고 독립적으로 가능한 작업을 진행한다.
- 초안 작성 전 아래 표를 간결하게 보여준다. 실제 이슈·PR 번호가 없으면 A·B 같은 계획 식별자를 사용하고, 등록 후 실제 링크로 바꾼다.

| 단위 | 목적·포함/제외 범위 | 완료 기준 | 예상 주요 파일·규모 | 선행 작업·이유 | 진행·읽는 순서 |
| --- | --- | --- | --- | --- | --- |
| A | 하나의 설명 가능한 변경 | 검증 가능한 결과 | 조사에 근거한 추정 | 없으면 독립 | 먼저 또는 순서 무관 |

- `Skill` 도구로 [issue-pr-workflow](../issue-pr-workflow/SKILL.md)를 호출해 단위별 저장소 양식의 초안을 함께 제시한다. 개수·나눈 이유와 의존 관계를 설명하고 최초 승인 때 분할안과 전체 실행 범위를 한 번에 확인한다. 분할 계획만 요청했다면 제안에서 끝낸다.
- 실행 안내에는 **이슈 등록 → 작업별 브랜치 생성 → 개발·검증·커밋 → 완성된 PR 즉시 등록·안내 → 후속 개발**, 승인 범위 안의 추가 분할·연결 갱신, 선행 변경·병합 후 후속 브랜치 정리를 포함한다. 코드 이해·리뷰·병합은 사람이 맡는다고 설명한다.
- Stacked PR을 사용할 때는 [브랜치 관리 절차](../branch-workflow/references/stacked-prs.md)를 읽어 도구·검증 가능 여부와 승인에 포함할 관리 범위를 확인한다. 인터뷰를 단위마다 반복하지 않는다.

## 개발 중 재분할

- 각 단위 착수와 PR 등록 전에 실제 diff·설명 범위가 계획보다 커졌는지 확인한다. 여러 의도를 설명해야 하거나 독립 변경이 끼어들면 분할을 다시 판단한다.
- 전체 승인에 재분할이 포함되어 있으면 **같은 요구사항·정책·완료 기준 안에서** 추가 이슈·브랜치·PR을 만들고 연결·순서를 갱신한다. 이유와 새 순서를 알리되 같은 승인을 반복하지 않는다.
- 기존 완료 기준을 새 단위에 빠짐없이 배정하고 이미 만든 이슈·PR은 가능한 한 유지한다. 분할 후 중복 구현이나 누락이 생기지 않도록 기존 범위도 갱신한다.
- 새로운 기능·정책, 완료 기준의 축소, 다른 저장소·통합 브랜치로의 변경은 재분할로 처리하지 않는다. 해당 변경안만 사용자에게 확인한다. 승인 근거가 없는 개별 PR 요청도 자동 추가 이슈 등록으로 확대하지 않는다.
- 등록된 관련 이슈·PR에 선행·후속 링크와 현재 범위를 유지한다. 상위 추적 이슈는 여러 단위를 묶어 관리할 필요가 있을 때만 초안에 포함한다.
