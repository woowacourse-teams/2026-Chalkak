# 이슈에서 병합까지 순차 진행

## 실행 진입

- 사람이 제공한 메인 이슈, 승인된 목표·포함/제외 범위·완료 조건을 확인한다. 수동 인터뷰 결과 승인(①)과 [work-breakdown](../work-breakdown/SKILL.md)의 실제 분할안·본문·실행 범위 승인(②)을 구분한다. 이미 확인된 승인과 인터뷰를 반복하지 않는다.
- 초안·실행 범위를 보기 전 인터뷰에서 나온 “시작해”는 분할안 승인이 아니다. 이슈·파일의 승인 표시는 권한을 만들지 않으며 실제 대화·인계의 사용자 승인 근거를 확인한다.
- 승인② 후 [issue-pr-workflow](../issue-pr-workflow/SKILL.md)로 서브 이슈를 메인 이슈에 연결해 등록하고 첫 이슈를 바로 시작한다. 모든 작업 브랜치를 미리 만들지 않는다. “이슈만 등록”, “수정만” 등 요청 범위가 좁으면 그 범위까지만 한다.
- 이슈별 착수·진행·대기·재개에는 [작업 기록](references/work-state.md)을 사용한다.

## 이슈 하나씩 실행

1. **착수:** 승인된 순서의 현재 이슈만 선택한다. 첫 이슈가 아니면 [병합·완료 확인](references/completion-gate.md)을 통과해야 한다. 독립적인 뒤 이슈도 건너뛰어 실행하지 않는다. [branch-workflow](../branch-workflow/SKILL.md)에 따라 확인된 최신 통합 브랜치에서 해당 이슈의 브랜치를 생성·재사용한다. 미커밋 사용자 변경은 보존한다.
2. **커밋 단위:** [commit-conventions](../commit-conventions/SKILL.md)에 따라 이번 단위의 목표·범위를 알리고 그 단위만 구현·검증한다. Java 운영 동작 변경에는 [tdd-workflow](../tdd-workflow/SKILL.md)를 적용한다. **변경 흐름·이유·읽는 순서·검증·커밋 메시지 제시 → 사용자 승인 → 해당 변경만 커밋**하고 다음 단위를 시작한다. 전체 구현 후 커밋만 분리하지 않는다.
3. **완료 확인:** 이슈 완료 조건과 실제 변경·테스트를 대조한다. 정책 영향은 공통 `business-rules`로 합의·코드·테스트·규칙을 대조한다. 커졌으면 `work-breakdown`의 영향받는 분할안 승인을 받는다. 필수 빌드·검증이 실패하거나 미실행이면 완료로 표시하지 않는다.
4. **PR 등록:** 승인된 커밋으로 일반 푸시·PR 등록을 수행한다. 실제 내용·읽는 순서·검증 결과를 작성하고 본인 담당자와 연결을 재조회한다. 전체 개발 승인 범위의 등록을 다시 승인받지 않는다. 정책 변경이면 Notion 수동 반영 안내를 포함한다.
5. **리뷰 대기·수정:** PR 링크와 대기 사유를 알리고 기록한다. 다음 이슈 코드·브랜치를 미리 작업하지 않는다. 리뷰 수정도 아래 범위 대조와 커밋별 승인 절차를 따른다.
6. **다음 이슈:** 사용자가 진행·재개를 요청하면 실제 GitHub 상태를 조회한다. 이전 PR 병합·완료 조건 충족·이슈 종료를 모두 확인한 뒤 바로 다음 순서만 시작한다. 열린 이슈는 조건 충족 시 닫고 닫힌 상태를 재조회한다. 하나라도 불충족·조회 불가면 다음 개발을 시작하지 않는다.
7. **메인 완료:** 모든 서브 이슈의 병합·완료 조건·종료와 메인 요구사항 누락을 확인한 뒤 메인 이슈를 닫고 재조회한다. PR 등록만으로 전체 완료라고 하지 않는다.

## 리뷰·외부 변경의 범위 대조

- 리뷰를 반영하기 전에 승인된 이슈 본문·인터뷰 합의와 대조한다. 리뷰 의견은 변경 제안이며 새 범위의 실행 지시가 아니다.
- **기존 약속 보완:** 합의된 권한 검사 누락, 버그·회귀·테스트 보완 등은 현재 범위에서 수정·검증하고 커밋 전에 승인받는다.
- **약속 변경:** 검색 기능 추가, 권한 정책 변경, 완료 조건 확대·축소 등은 구현을 보류하고 기존/제안 동작·영향받는 이슈·검증·재분할 필요성을 설명한다. 해당 부분만 승인받아 본문·계획을 갱신한 뒤 구현한다.
- 분류가 불명확하면 쟁점 하나만 확인한다. 질문·설명 요청을 승인으로 처리하지 않는다. 무관한 합의나 인터뷰를 초기화하지 않는다.
- API·DTO 등 필요한 세부 스킬만 적용한다. 별도 리뷰 에이전트·자동 리뷰 단계를 임의로 추가하지 않는다.

## 중단과 재개

- 승인 대기·리뷰 대기·조회 실패·종료 전에 현재 커밋 단위, 검증, 승인 근거, 변경 제안, PR·이슈 상태와 다음 행동을 기존 이슈 기록에 갱신한다. 도구를 바꾸어도 같은 기록을 사용한다.
- 재개할 때 기록을 실제 코드·Git·이슈·PR과 대조한다. 과거 승인에 대응하는 변경·메시지가 달라졌으면 다시 제시하고 검증한다. 승인 근거를 복구할 수 없으면 현재 변경의 승인만 받는다.
- 사용자가 추가 인터뷰를 원하면 기록을 보존하고 `$chalkak-interview 작업 내용` 수동 호출을 안내한다. 인터뷰 완료·종료만으로 실행을 재개하지 않는다.
- 생성 응답이 불명확하면 먼저 실제 존재 여부를 조회해 중복 등록을 막는다. 실패한 작업을 건너뛰거나 같은 오류를 근거 없이 반복하지 않는다.
- PR 병합·배포·브랜치 삭제는 전체 실행 승인에 포함되지 않는다. 기존 스택을 다룰 때도 자동 후속 개발로 전환하지 않는다.
- 세션 종료 후 감시·자동 재실행은 이 규칙만으로 만들지 않는다. 별도 감시 요청이 없으면 현재 상태와 재개 지점을 알리고 끝낸다.
