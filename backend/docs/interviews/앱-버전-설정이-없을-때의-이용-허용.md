# 앱 버전 설정이 없을 때는 이용을 허용한다

- 갱신일: 2026-10-29
- 관련 PR: [#851](https://github.com/woowacourse-teams/2026-Chalkak/pull/851)
- 관련 이슈: [공개 조회 #847](https://github.com/woowacourse-teams/2026-Chalkak/issues/847), [관리자 설정 관리 #848](https://github.com/woowacourse-teams/2026-Chalkak/issues/848)

최초 기획에서는 실제 버전과 스토어 주소를 미리 알아야 조회 API의 초기 데이터를 넣을 수 있다고 보았다. 사용자 요구는 두 값을 관리자 페이지에서 입력·수정하는 것이었다. 실제 값이 아직 없다는 사실은 조회 API 개발을 막는 조건이 아니었다.

남은 질문은 관리자가 처음 저장하기 전에 앱이 조회하면 어떻게 동작하는가였다. 서버가 미설정을 404로 알리는 방식을 먼저 물었지만, 사용자가 결정해야 할 것은 상태 코드보다 앱 이용 가능 여부였다. 사용자는 이 상태에서 업데이트 제한 없이 이용하도록 선택했다.

조회는 플랫폼과 버전·주소의 명시적인 null을 200으로 반환한다. 임의의 낮은 버전이나 예시 주소를 만들지 않고, 앱은 정상 미설정 응답에서 비교와 스토어 이동을 건너뛴다. 한 플랫폼만 설정됐다면 다른 플랫폼은 계속 미설정이다.

이 선택은 통신 실패 정책까지 정한 것이 아니다. 서버 응답을 못 받은 경우의 마지막 설정 사용·재시도·진입 처리는 미확정이다. 관리자 최초 입력 API는 #848에서 구현했으며 관리자 웹 화면은 별도 작업이다.

현재 정책 원본은 [앱 최소 지원 버전 규칙](../../../docs/business-rules/rules/app-version.md)이다. 공개 조회의 미설정 null 응답·플랫폼 분리·캐시 방지·인증·문서 계약은 테스트로 확인했다. 조회 정책의 검증은 #847에서 확인했고 관리자 저장은 #848에서 이어서 구현·검증했다. 앱 화면 연동은 별도 작업이다.

관리자 저장을 진행하면서 운영 기준의 적용 대상이 다시 드러났다. 버전 하향, 같은 값 재저장, 사유 길이, 출시 확인은 일반 사용자의 앱 조작 규칙이 아니라 관리자 설정 저장 규칙이다. 사용자는 이를 확인한 뒤 잘못 올린 버전을 낮출 수 있게 하고, 같은 값 재저장은 이력과 시각을 유지하며, 사유는 앞뒤 공백 제거 후 1~500자로 적용하기로 했다.

실제 스토어 주소도 관리자에게 입력받는다. 개발 시점에 고정된 앱 ID를 알아야 한다는 전제를 두지 않고 공식 스토어 주소·앱 ID의 형식만 서버에서 검증하며, 실제 Chalkak 앱인지와 설치 가능 여부는 관리자가 확인한다. 버전은 각 숫자 0~2,147,483,647, 앞자리 0 금지로 합의했다. 관리자 저장·감사는 같은 변경 단위로 검증하며, 공개 조회의 미설정 계약은 유지한다. #848의 세부 계약은 [관리자 연동 안내](../../../docs/business-rules/guides/admin-app-versions.md)에서 관리한다.

리뷰에서는 VO 생성자가 DB 조회에도 실행되어 예전 주소나 공백이 조회를 막을 수 있음이 드러났다. 입력에서는 앞뒤 공백을 제거하지만 DB 조회에서는 원문을 바꾸지 않도록 분리했다. 기존 값은 배포 전 같은 VO와 감사 값 검사로 확인하며, 부적합한 값을 예시 값으로 자동 교체하지 않고 담당자가 확인하도록 시작을 중단한다. 이 선택은 부적합한 데이터가 있을 때 자동으로 배포를 성공시키는 해결책이 아니다. 운영 DB의 실제 값은 별도로 확인해야 한다.
