# 사인에서 작성자의 공개 사진을 탐색하는 방법

- 갱신일: 2026-10-19
- 관련 이슈: [#679](https://github.com/woowacourse-teams/2026-Chalkak/issues/679), [#680](https://github.com/woowacourse-teams/2026-Chalkak/issues/680), [#681](https://github.com/woowacourse-teams/2026-Chalkak/issues/681), [#682](https://github.com/woowacourse-teams/2026-Chalkak/issues/682)

## 주제별 피드에서 한 사람의 사진으로 이동하기

기존 피드는 특정 주제 날짜의 사진을 조회하고, 캘린더는 로그인한 본인의 기록만 조회한다. 사용자는 사인을 눌렀을 때 그 사람이 지금까지 올린 공개 사진을 별도 페이지에서 계속 보고 싶어 했다. 전체 사진을 한 번에 반환하지 않고 20개씩 이어서 보는 방향에 합의했다.

사인 이미지 URL은 교체될 수 있으므로 작성자를 연결하는 기준으로 쓰지 않는다. 진입 게시물 ID로 서버가 작성자를 찾는 방법과 회원 ID를 직접 사용하는 방법을 비교했다. 사인이 바뀌거나 진입 게시물이 삭제되어도 같은 작성자를 조회할 수 있도록 고정된 `authorId`를 기존 피드·상세에 추가하는 방식을 선택했다. 비로그인 피드에도 ID를 제공하되 새 모아보기 API는 로그인을 요구한다. 이로써 같은 작성자를 식별할 수 있는 범위를 넓힌다는 점도 인터뷰에서 확인했다.

## 사진과 주제를 보고 궁금한 사진만 상세 조회하기

목록에 사진 제목·좋아요까지 담으면 상세 호출을 줄일 수 있다는 제안이 있었지만, 사용자가 원하는 것은 사진·게시물 ID·주제로 탐색하고 사진을 선택했을 때 기존 상세를 보는 흐름이었다. 목록에는 이에 필요한 정보만 담는다. 본인이라도 승인 전 사진을 보여주지 않으며, 승인·삭제·탈퇴 조건은 기존 공개 정책을 유지한다.

정렬을 제출 시각과 주제 날짜 중 선택하도록 물었지만, 날짜별 주제 하나·주제별 공개 사진 하나·겹치지 않는 참여 기간이라는 현재 제약에서는 정상 제출의 두 순서가 일치함을 확인했다. 불필요한 구분을 바로잡고 사용자가 이해하기 쉬운 주제 날짜 최신순을 선택했다.

이미 지나온 날짜의 사진이 뒤늦게 승인돼도 보는 도중 목록에 끼워 넣지 않고 새로고침·재진입 때 반영한다. 미조회 구간은 요청 시점의 공개 조건을 따른다. 사진이 없는 정상 회원은 빈 목록, 없거나 탈퇴한 작성자는 `404`로 구분한다.

## 기능별로 완성해 검토하기

한 이슈 또는 두 이슈로 묶은 초기 제안은 예상 변경량에 비해 컸고, 다섯 이슈 안은 주제 정보와 피드·상세 ID를 지나치게 나눴다. 최종적으로 최근 20장 조회(#680), 커서 이어보기(#681), 기존 피드·상세의 작성자 ID와 사인 연결(#682)이라는 세 단위를 승인받았다. 각 단위의 관련 테스트·Swagger·정책·연동 설명서는 같은 변경에 포함한다. 개발 검토에서는 기존 피드처럼 요청 DTO에서 기본 20개와 허용 범위 1~100개를 정하고, 서비스는 요청한 개수를 전달하도록 합의했다. 기본 사용 흐름은 20개씩 탐색하며 조회 크기만 선택할 수 있다.

현재 구현 대상은 #680이다. #681의 커서와 #682의 `authorId`는 아직 구현하지 않는다. 이 기록은 전체 탐색 기능의 방향 합의이며 구현·검증 완료를 뜻하지 않는다. 현재 정책은 [게시물 규칙](../../../docs/business-rules/rules/post.md), 현재 API 제공 범위는 [연동 안내](../../../docs/business-rules/guides/author-public-posts.md)를 기준으로 확인한다.
