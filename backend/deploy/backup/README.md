# DB 별도 백업

`db-backup.sh`는 PostgreSQL 18의 단일 DB를 custom 형식으로 내보내고 rclone으로
별도 저장소에 전송한다. RDS 자동 백업과 시점 복구를 대체하지 않는다.
실제 사진 파일은 포함하지 않으며 이미지 백업은 #843의 범위다.

## 현재 범위

- #842 커밋 1: 수동 백업 생성·전송·검증. 복구 도구·실제 복원 시험은 다음 커밋에서 추가한다.
- #844: 실제 팀 S3 권한, 운영 보관본 복구 검증, 매일 자정(Asia/Seoul) 예약 실행 적용.
- DB 파일은 최소 7일 보존 목표다. 현재 자동 삭제는 없으므로 실제로는 더 오래 쌓인다.
- 아직 이 문서와 스크립트만으로 자동 백업이나 운영 복구가 검증된 것은 아니다.

## 준비

Linux에 Bash, PostgreSQL 18의 `pg_dump`·`pg_restore`, rclone, `sha256sum`, `cmp`가 필요하다.
DB에 직접 연결해 스키마·테이블·시퀀스를 내보낼 권한이 있어야 한다.
TLS 인증서 검증을 위해 RDS CA 번들을 준비한다. 스크립트는 `verify-full`을 강제한다.

`backup.env.example`을 Git 밖의 보호된 위치에 복사해 실제 설정을 채운다.
백업 설정 파일은 `source`로 읽으므로 실행 사용자가 신뢰하는 파일만 사용한다.
설정, pgpass, rclone.conf는 실행 사용자만 읽도록 소유권과 mode 600을 지정한다.
인증서도 해당 사용자가 읽을 수 있어야 한다. 앱 설정이나 CD 필수 키는 변경하지 않는다.

pgpass 형식은 `호스트:포트:DB:사용자:비밀번호`다. 특수 문자는 libpq 규칙대로 이스케이프한다.
PGPASSWORD나 명령 인자로 비밀번호를 전달하지 않는다. 소스·대상 주소를 로그에 남기지 않는다.
백업 전용 rclone remote는 팀 S3를 가리키게 하고 생성·조회 권한만 부여한다.
삭제·설정 변경 권한은 주지 않는다. 업로드와 전체 내용 검증이 가능해야 한다.

## 수동 실행

```bash
bash deploy/backup/db-backup.sh /etc/chalkak-backup/backup.env
```

날짜는 UTC로 기록하며 예약 실행의 한국 시간 기준과 구분한다.
설정 예제를 그대로 쓰면 실제 DB·S3로 연결하지 못한다.
이 스크립트는 백엔드 CodeDeploy나 앱 시작 과정에 연결하지 않는다.

```text
팀 버킷/chalkak/db/
└── chalkak-db-실행UTC시각-고유문자열/
    ├── database.dump
    ├── database.dump.sha256
    └── COMPLETE
```

`pg_dump` 성공 → 비어 있지 않은 파일·목차 확인 → SHA-256 생성 → 파일·체크섬 전송
→ `rclone check --download`로 원격 내용 비교 → COMPLETE 업로드·재조회 순서다.
서로 다른 실행은 고유 경로를 사용하고 `--immutable`로 기존 내용 교체를 제한한다.
목차 조회는 실제 DB 복원 검증을 대신하지 않는다.

완료 표시는 파일 전송·내용 검증이 끝난 회차에만 작성한다. 복원 가능한 회차를 고를 때
COMPLETE, 체크섬 파일, 백업 파일을 함께 확인한다. 완료 표식 자체는 위변조 방지 서명이 아니다.
네트워크 오류가 나면 표식 업로드가 성공했는데 응답만 실패할 수도 있어 원격 결과 확인이 필요하다.

실패하면 0이 아닌 종료 코드와 `FAILED stage=... run=...`를 남긴다.
단계는 configuration, dump, archive-list, checksum, upload-dump, upload-checksum,
verify, completion이다. 외부 명령의 원문 진단은 민감 정보 노출을 막기 위해 출력하지 않는다.
실패 시 부분 업로드가 남을 수 있지만 원격 파일은 자동 삭제하지 않는다.
재실행하면 새 회차를 만든다. 성공·실패·정상 종료 신호에서 이번 로컬 임시 경로만 정리한다.
강제 종료(SIGKILL)·호스트 장애에서는 임시 파일이 남을 수 있어 접근 권한과 디스크를 확인한다.

## 제한과 시험

파일 내용 검증을 위해 원격 파일을 다시 읽으므로 추가 읽기·전송과 실행 시간이 발생한다.
덤프와 다운로드 비교는 운영 DB의 읽기·EC2 자원을 사용한다. 크기·부하·시간은 실측한다.
DB 변경에 대한 일관성은 pg_dump가 제공하지만 S3 이미지와 같은 시점의 원자적 백업은 아니다.
역할·권한·테이블스페이스와 RDS·네트워크 설정은 별도 재현이 필요하다.
`--no-owner --no-privileges`를 사용하며 원래 소유권·접근 정책까지 복원한다고 간주하지 않는다.
기본 연결 제한은 10초, 테이블 잠금 대기는 10초, SQL statement timeout은 5분이다.

```bash
bash deploy/backup/tests/db-backup-test.sh
```

합성 DB 도구와 테스트 파일로 정상·실패 처리를 시험한다. 실제 운영 DB, AWS 권한,
pg_dump 파일의 실제 복원 여부는 이 시험만으로 검증하지 않는다.
